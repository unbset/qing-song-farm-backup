# 产品分析：农村大席（团建 / 宴会）

> **分析框架**：产品分析框架V4
> **分析日期**：2026-05-29（V4升级）
> **分析者**：AI（多角色切换）
> **产品状态**：规划中，需确定菜单方案、定价、执行流程后上线
> **归属板块**：引擎A（餐饮）

---

## 1. 飞轮定位

**主定位**：利润中心

农村大席是引擎A中面向B端团体的高客单价产品。一次性上菜、服务人力需求低、食材成本可控、溢价空间大。它是填充工作日（团建）和节假日（宴会）现金流的有效工具。

**辅助作用**：
- 传播杠杆（大席一次性摆满的画面——"排面"感强，天然适合拍照传播）
- 复购锚点（团建客户今年办了大席，明年还会想到农场）

---

## 2. 目标客群

### 团建客户（工作日主力）

**企业团建**：
- 画像：潍坊本地中小企业，团队15-40人。决策者是行政/HR，30-45岁女性为主，预算敏感
- 痛点：每次团建都在市区餐厅吃饭，没新意；员工对"换个地方开会+吃饭"的模式已厌倦；预算有限，人均超150元老板批不下来
- 痒点："能让员工发朋友圈的团建"——行政被同事夸"这次团建不错"的成就感
- 决策逻辑：找团建场地 → 看到农场有松林+大席 → 人均100出头能吃得很丰盛 → "比去酒店有意思" → 选这里

### 宴会客户（周末/节假日）

**寿宴/家庭聚会/同学会/公司年会**：
- 画像：20-50人规模，决策者是家中晚辈或活动组织者
- 痛点：在酒店办宴会"不过就是换个大厅吃饭"；想找不一样的地方，又怕不够正式被长辈说
- 痒点："在松林里办酒席"——既满足"不一样"，因是一桌桌摆好的大席又不失"正式感"
- 决策逻辑：家里要办寿宴/同学会 → 有人提议农场 → 来实地看场地 → 看菜单样图 → "环境可以、吃得讲究、价格合适" → 定

---

## 3. 核心体验

"一长排桌子从这头摆到那头，凉菜热菜一道道上齐了，大家自己夹，没有服务员在旁边等着加茶倒酒——爱怎么吃怎么吃，没人管你。"

这不是酒店宴席那种"端着"的体验。它是农村大席那种"摆开了、坐下了、开吃"的直爽感。不需要转桌、不需要等服务员分菜、不需要遵循什么用餐礼仪——坐下来就是吃。

---

## 4. 交付标准

### 触点一：场地布置的第一印象

| 角色            | 加分                                        | 扣分                       |
| :------------ | :---------------------------------------- | :----------------------- |
| **员工**        | 在松林下摆好长桌，铺红白条纹桌布，每桌放一瓶农场自采野花。大席PLus（需讨论）？ | 几张折叠桌拼一起，上面什么都没铺，像临时搭的   |
| **主管**        | 大席区布置和宣传图片一致——客户来了说"比图片还好看"               | 实物和图片差距大                 |
| **客户（团建组织者）** | 同事们到了说"哇，这个布置可以啊"——组织者觉得有面子               | 场地看起来简陋，同事嘴上没说但脸上写着"就这？" |

### 触点二：上菜环节

| 角色 | 加分 | 扣分 |
|:---|:---|:---|
| **员工** | 一次性上齐（凉菜先上，热菜陆续出），不拖沓 | 一道菜等十分钟——没有大席的"气势"了 |
| **主管** | 上菜速度取决于后厨出餐能力。大席的优势是"一次性备好一次性上"——做不到则优势丧失 | 变成轮流上菜，和普通团餐没区别 |
| **客户** | "菜上得好快"——感觉丰盛、实在 | "怎么等这么久"——期待的是"摆满一桌"而非一道一道等 |

### 触点三：散席后的印象

| 角色 | 加分 | 扣分 |
|:---|:---|:---|
| **员工** | 临走问一句"吃得怎么样？有要打包的吗？"——有大席的习俗 | 收了桌就走 |
| **主管** | 给组织者发微信："今天还满意吗？有需要改进的随时说。"——决定明年是否续约 | 无后续跟进 |
| **客户（组织者）** | 同事回去后在群里说"今天那顿饭不错"——组织者心里踏实了，明年还选这里 | 同事回去没人提起——"和其他地方也没区别" |

### 品质底线
- 所有菜品约定时间内上齐（凉菜20分钟内、热菜40分钟内）
- 每道菜份量不少于标准菜单规定
- 菜品温度达标（热菜上桌冒热气）
- 每道菜留样48小时（食品安全）
- 每场宴席前与客户确认菜单，当日不可更换（备好的菜换不了）

| :--- | :----------------------------------------- | :-- | :-- | :-------------------------------------------------- | :--- |
| 运营风险 | 后厨出餐能力不足：同时接两场（各30人）无法按时出完60人份菜品           | 中   | 高   | 正式上线前做满负荷测试，摸清单场出餐上限；接单不超过上限                        | 可承受  |

| 安全风险 | 食品安全事故（食物中毒/异物投诉）                          | 低   | 极高  | 每道菜留样48小时；不供应生食（刺身、生腌）；定期员工食品安全培训                   | 可承受  |

## 8. 增长路径

### 复购机制
- 团建客户保持年度回访（组织者可能换工作，但关系在）
- 宴会客户（寿宴/聚会）：场景复购率低（谁家每年办寿宴？）——但参与者可能转化为散客
- 大席菜单按季度轮换（春季加野菜、秋季加螃蟹），让再次选择的客户有新鲜感

### 传播机制
- 大席一次性摆满的画面天然适合拍照——作为团建/宴会的"排面"
- 松林下摆长桌的差异化场景本身就是一个传播点（"在农场吃大席"——这个概念有记忆点）
- 建议：每场大席结束时帮客户拍一张"全体大合影"（松林+长桌+丰盛菜品做背景）

### 衍生可能
- 夏季版：减少重油菜品，增加凉菜比重
- 冬季版：增加炖菜、锅仔类
- 团建版：增加"开饭前由农场方简短致辞：欢迎XX公司来青松农场"——让组织者被重视
- 寿宴版：增加"长寿面"环节（面现煮，由农场人员端上）
- 年会版：大席+篝火晚会联办（引擎B配合）

**边界判断**：如果从"团建/宴会专用"扩展到"散客零点"，核心体验变了（大席的精髓是一次性摆满一桌的"壮吃"场面，不能拆成单点），所以不为散客开放大席是合理的。

## 10. 决策结论

| 项目   | 内容                                                      |
| :--- | :------------------------------------------------------ |
| 总体判断 | **条件做**                                                 |
| 前提条件 | 1. 完成出餐能力测试（确定单场最大人数）2. 确定三档标准菜单（含食材采购清单）3. 确认雨天室内备用空间  |
| 优先级  | **中**。大席不是引流产品，是"引擎B接团建/宴会时的配套产品"。引擎B接到大单时再启动，不主动打广告    |
| 启动建议 | 先完成出餐能力测试（选一个工作日在后厨模拟60人份出餐）→ 确认上限后接第一单 → 实战后迭代菜单和流程    |
| 退出条件 | 连续6个月月均大席场次<1场→暂停，用室内餐代替；连续2场满意度<4/5→暂停排查；食品安全事件→立即停业整改 |

## +1 客户视角验证（AI多角色模拟）

### 角色A：企业行政（为公司20人团建选场地）

**决策路径**：找团建场地 → 看到青松农场有大席 → 对比其他场地 → 周末先来实地看一趟

**加分点**：松林下摆长桌比照片好看；三档价格选择清晰，人均100出头能吃得丰盛；看到其他客人照片"有点意思"
**扣分点**：无（如有雨天顾虑，提前告知有室内空间即可打消）
**复购意愿**：强。如果这次同事满意，明年续约概率高。
**传播意愿**：会。组织者会发朋友圈"今天公司团建在农场"。

### 角色B：来参加寿宴的亲戚（60岁退休阿姨）

**体验路线**：大姐寿宴在农场办 → 自己开车过来 → 看到松林下长桌 → 落座 → 菜上来了 → 吃完回家

**加分点**："这个地方好，空气好"；"有鱼有肉有鸡有菜，挺像那么回事"；"比在酒店办划算多了"
**扣分点**：无（大席的品质不取决于精致程度，而取决于"和价格比，值不值"）
**复购意愿**：中（她自己不会来办宴席，但会推荐给朋友："那个农场不错"）
**传播意愿**：会。拍了照片发家族群——群里其他人问"在哪在哪"。

### 角色C：农场主管（运营视角）

**核心运营优势**：
- 人力需求低。一个人可服务三桌（约30人），比室内餐效率高
- 对厨师依赖低。菜品以凉菜+蒸炖卤为主，凉菜可提前一天备好，中心厨房操作员培训后可完成
- 食材成本可控。菜单固定，批量采购/从核心领取，无"客户单点"带来的库存不可控
- 与引擎B协同成熟。引擎B接团建订单时，大席直接嵌入套餐

**盲点发现**：大席目前设计聚焦"做给客人看"，但忽略了**下雨天的备选方案**。如果大席预设室外，下雨时能否快速转移到室内？室内容纳量是否够？需提前准备好。
