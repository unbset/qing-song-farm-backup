[SOP编号] G-04
[SOP名称] 跨板块活动协调流程
[执行人] 言渊（总协调）
[替代人] 运营卫星成员（日常协调）/ 引擎A或B主理人（临时代理）
[执行时间] 活动确认后即时启动 → 活动前每日晨会 → 活动后总结复盘
[适用季节] 全年
[前置条件] 活动已确认（团建/课程/宴会/特殊节日活动）
[AI接口] Hermes生成活动总日程表，同步至各板块负责人；自动推送各板块待办事项
[AI提醒] Hermes在活动前7/3/1天推送各板块准备清单；活动当日在各关键节点推送提醒

---

### 一、活动确认阶段

```
1. 活动信息录入
   - 运营卫星在Hermes创建活动档案
   - 填写：活动名称/日期时间/人数/客户类型/活动内容/预算/联系人
   - 标注涉及板块（核心层/引擎A/引擎B/自然手作/运营卫星）

2. 板块影响评估
   - 评估活动对各板块正常运营的影响
     - 引擎A：用餐人数是否在产能范围内
     - 引擎B：是否影响散客露营和营位
     - 核心层：采摘区是否被大量占用
     - 自然手作：手作导师是否有空档
   - 评估结果直接影响可否接单
```

### 二、活动前协调

```
1. 活动前7天
   - 言渊主持首次协调（可在Hermes中发起）
   - 确认各板块负责人和职责
   - 确认时间线和关键节点
   - 识别风险点（天气/人员/物资）
   - 制定备选方案

2. 活动前3天
   - 各板块在Hermes中提交准备进度
   - 言渊检查各板块准备情况
   - 确认外采/租赁物资到位时间
   - 与客户最后一次确认人数和方案

3. 活动前1天
   - 晨会（5分钟）各板块确认准备就绪
   - 场地布置协调（哪个板块先布置？先后顺序）
   - 人员协调：各板块人手是否够用？需不需要支援？
   - 天气确认，备选方案启动判断
```

### 三、活动当天执行

```
1. 活动前1小时
   - 言渊或运营卫星整体巡检
   - 各板块自行确认准备状态
   - 在Hermes标记"准备就绪"

2. 活动进行中
   - 各板块按活动日程表执行
   - 各板块之间按时间线衔接：
     到达 → 参观 → 体验 → 用餐 → 自由活动 → 返程
   - 板块衔接处设置"信号点"：
     上一环节结束前15分钟，通知下一环节负责人准备
   - 言渊或运营卫星在关键衔接点现场确认
```

### 四、板块衔接矩阵

```
关键衔接节点对接方式：

| 时间 | 环节 | 负责板块 | 通知下一个板块 |
|:---|:---|:---|:---|
| T-0 | 到达迎接 | 运营卫星 | → 参观引导 |
| T+30min | 参观结束 | 运营卫星 | → 体验/引擎A |
| T+1h | 体验结束 | 核心层/自然手作 | → 引擎A用餐 |
| T+2h | 用餐结束 | 引擎A | → 引擎B/自由活动 |
| T+4h | 篝火/结束 | 引擎B | → 运营卫星送别 |

每个衔接节点，前一板块负责人需在Hermes标记"环节完成"。
```

### 五、活动后协调

```
1. 场地恢复
   - 各板块各自恢复负责区域
   - 公共区域由运营卫星统一检查
   - 跨板块占用的场地（如：引擎A区域被活动占用，活动结束后第一时间恢复）

2. 活动复盘
   - 活动结束后24小时内进行（可线上）
   - 各板块反馈：
     - 做得好的地方
     - 遇到的问题
     - 对协调的建议
   - 言渊总结并更新活动SOP

3. 客户反馈收集
   - 运营卫星收集并录入Hermes
   - 各板块查看反馈中涉及本板块的内容
```

### 六、验收标准

```
□ 活动信息已录入Hermes，涉及板块已确认
□ 活动前各板块准备完毕，无遗漏
□ 活动当天各环节按时间线顺利推进
□ 各板块衔接顺畅，无空档或等待
□ 活动后场地已恢复
□ 活动复盘已完成，改进点已记录
□ 客户满意度≥4.5分（5分制）
```

### 七、异常处理

| 异常 | 响应 |
|:---|:---|
| 某板块准备未完成 | 优先保障客户体验，延迟环节调整顺序 |
| 人力不足 | 优先保障客户直接接触的岗位，向兼职或言渊求援 |
| 天气突变影响户外环节 | 启动备选方案（室内/雨棚/调整先后顺序） |
| 客户迟到/提前 | 通知所有板块调整时间线 |
| 某一环节超时 | 后续环节压缩非核心部分 |
| 跨板块冲突（同时两组团建） | 分组分路线：一组走A路线用餐，一组走B路线体验 |

### 八、跨板块协作（本SOP本身就是跨板块机制）

本SOP是跨板块协调的标准流程，各板块在与客户相关的活动中应参照本流程执行。

日常运营中各板块间的小型协作（如：引擎A需要核心层送鸡蛋），不启动此流程，直接对接即可。

本流程适用于任何涉及≥2个板块的客户活动。

### 九、客户触点

- 跨板块协调质量直接决定客户体验的"流畅度"
- 客户不需要知道协调过程，但能感受到"每个环节都被提前想到了"
- 衔接处是客户最容易感受到"断裂"的地方（等人/等待/不知道该做什么）
- 所有衔接处设置"引路人"，不让客户在农场内茫然张望
