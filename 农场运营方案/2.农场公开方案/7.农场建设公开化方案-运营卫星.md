# 农场建设公开化方案 · 运营卫星

> **基于**：星形结构 — 运营卫星（保障中心）
> **覆盖工作**：13项（O01-O13）
> **本文定位**：运营卫星所有可公开化工作的模式匹配与执行设计

---

## 第一部分：总纲

### 1.1 核心理念

运营卫星是所有板块中"最小众但最关键"的公开化板块。

其他四个板块的公开化都是"面向客户的"——让客户参与农事、餐饮、露营、手作。而运营卫星的公开化有两个截然不同的受众：

- **对内公开（团队）**：财务透明（O05/O06）、团队协作（O12/O13）——这是利益共同体的基础，面向的是团队成员
- **对外公开（客户/公众）**：品牌内容（O01-O04）、安全巡检（O07/O09）、零售交付（O10/O11）——这些面向的是客户

运营卫星的公开化原则：**该透明的透明，该保密的保密**。

### 1.2 运营卫星公开化的三条原则

| 原则 | 说明 |
|:---|:---|
| **对内透明是对外公开的前提** | 财务月报先对团队全员透明，团队信任建立后，再将部分数据（如农场营收趋势、食材成本占比等）以"年报/季报"形式对会员公开 |
| **不公开低质量信息** | 运营卫星产出的内容代表农场的品牌形象。宁可不发，也不发粗糙的、随意的、不审核的内容 |
| **安全与合规不妥协** | 安全检查记录、应急预案等可以公开的部分可以展示，但涉及客户隐私的数据（姓名/电话/消费记录）任何时候都不能公开 |

### 1.3 运营卫星五种模式的整体倾向

运营卫星的公开化不适合"共建化"和"劳动换薪"——这个板块不直接面对客户，内部工作没有外部参与的基础。主要适用三种模式：

| 模式 | 适合什么工作 | 说明 |
|:---|:---|:---|
| 课程化 | 安全知识科普、零售产品背后的故事 | 将安全巡检、产品打包等过程转化为内容 |
| 认领化 | 不适用 | 运营卫星不生产可认领的实物资产 |
| 技能传承 | 品牌内容制作技能的传递 | 教各板块主理人如何自己产出内容 |

## 第二部分：各模式详述

---

### 模式1 课程化

运营卫星的课程化主要体现为"将内部工作转化为品牌内容"——不是收费课程，而是"内容产品"。

#### 内容产品1：农场日记/这周农场发生了什么（对应O03）

| 项目 | 内容 |
|:---|:---|
| 形式 | 每周1条图文或1-2分钟短视频 |
| 内容 | 各板块的亮点瞬间（面包出炉/客户活动/菜地变化/长搭客户的日常）+ 下周预告 + 一个"本周特别感谢"（感谢某位客户/帮了大忙的人） |
| 发布渠道 | 视频号+公众号+社群+朋友圈 |
| 公开化价值 | 这是运营卫星最核心的内容产品，让关注者形成"每周必看"的期待感 |

#### 内容产品2：农场安全日记（对应O07）

安全巡检过程本身不性感，但把它做成"我们为了你的安全做了什么"的内容，就有信任价值。

| 项目 | 内容 |
|:---|:---|
| 形式 | 每月1条图文（"本月安全检查报告"） |
| 内容 | 本月检查了哪些区域、发现了什么问题、怎么解决的、下月检查重点 |
| 发布渠道 | 社群+会员群（不对全公开，面向到过店的客户） |
| 公开化价值 | 客户看到"这个农场每个月在检查灭火器和急救箱"——安全信任感建立 |

#### 内容产品3：零售产品开箱——反向的（对应O10）

别人做"开箱视频"，运营卫星做"装箱视频"——记录一份面包或手作产品是怎么从农场打包好发出去的。

| 项目 | 内容 |
|:---|:---|
| 形式 | 30-60秒短视频 |
| 内容 | 面包从出炉→晾凉→切片→包装→贴标→装箱→贴快递单→发出的全过程 |
| 发布渠道 | 社群+视频号 |
| 公开化价值 | "原来我收到的面包是这样打包的"——过程透明建立信任 |

---

### 模式5 技能传承

运营卫星的技能传承主要体现为：把内容制作能力传递给各板块主理人，让每个板块都能自主产出内容。

#### 典型场景：教各板块主理人拍短视频（无编号，新增内容）

| 项目 | 内容 |
|:---|:---|
| 形式 | 每月1次15分钟的简短视频技巧分享 |
| 地点 | 在各板块的工作现场，实操教学 |
| 内容 | "手机拍食材怎么拍好看""怎么30秒剪一个视频""什么光线适合拍露营场景" |
| 说明 | 运营卫星负责人不是在"替各板块做内容"，而是在"教各板块自己做内容"。这是运营卫星长期的核心价值——提高全农场的内容产出能力 |

---

### 财务透明机制（对应O05/O06）

财务透明不属于五种模式中的任何一种，但它是运营卫星最重要的"对内公开化"工作。单独描述。

#### 经营月报制度

**频率**：每月1次，月初第3个工作日内完成
**内容**：一张表（详见附录A模板），包含以下信息：
- 各板块月营收（引擎A/引擎B/自然手作/零售/其他）
- 各项支出（食材成本/人工底薪/提成分红/营销费用/管理费用/其他）
- 月净利润及累计净利润
- 各板块的分成计算依据

**公开范围**：团队全员（厨师、各主理人、运营卫星负责人、言渊）

**发放方式**：
1. 言渊花1小时填表
2. 发到团队群
3. 每月安排30分钟经营复盘会，言渊念一遍数字，解释"这个月收入为什么高了/低了"
4. 当场确认每个人的提成/分红金额
5. 疑问当面解答

**透明与不透明的边界**：

| 透明 | 不透明 |
|:---|:---|
| 各板块月营收 | 引擎A的利润率详细拆解 |
| 各人工支出合计 | 具体每个人拿多少钱（隐私） |
| 月净利润 | 农场主的个人收入和使用 |
| 提成/分红的计算过程和结果 | 未被采用的预算提案 |

## 第四部分：执行流程

运营卫星的执行流程不按"发现→评估→设计→执行→收尾"展开（与其他板块不同），而是按"内容日历"的方式管理。

### 4.1 运营卫星的内容日历

| 频率 | 动作 | 编号 |
|:---:|:---|:---:|
| 每日 | 拍一张"今天农场"的照片，配一句话发社群 | O01 |
| 每周 | 一周内容数据整理（各平台曝光量/互动量/新增关注） | O02 |
| 每周 | 发布"农场日记"（本周回顾+下周预告） | O03 |
| 按活动排期 | 活动预告图文制作与发布 | O04 |
| 每月 | 经营月报编制与公示（团队内部） | O05 |
| 每月 | 月度经营复盘会 | O06 |
| 每月 | "安全日记"发布（社群/会员群） | O07 |
| 每月 | 15分钟手机短视频教学（对各板块主理人） | 技能传承 |
| 按订单 | 零售产品的"装箱视频"拍摄与发布 | O10 |
| 每季度 | 新人入职引导的内容记录 | O13 |
| 每半年 | 应急演练记录与发布 | O09 |

### 4.2 各板块内容提交流程

运营卫星的核心工作之一是确保各板块按时提交内容素材。流程如下：

周一上午：各板块主理人在群里发本周内容计划

```
言渊：我周三拍"农场日记"——这周讲堆肥
引擎A：周二拍窑鸡 + 周六拍柴火灶客户
引擎B：周三拍松林晨光 + 周五发周末活动预告
自然手作：周六有课会拍花絮
核心层：周四拍酵素翻桶进度
```

运营卫星职责：
- 周一收集各板块计划 → 标注到内容日历
- 各板块发布前审核（确保调性一致+包含"到店理由"四要素）
- 发布后追踪数据 → 每周汇总
- 连续2周未按计划发布的板块 → 私聊问"是没时间还是遇到什么问题"

## 第五部分：风险与合规

### 5.1 经营月报的保密边界

经营月报对团队内部完全透明，但：
- 不对外部公开（不发给客户/不在社交媒体发布）
- 不包含个人薪资明细（只列各板块人工合计）
- 不在月报中点评个人工作表现（复盘会口头沟通）

### 5.2 客户隐私保护

运营卫星管理的客户信息（姓名/电话/消费记录/偏好）：
- 仅用于农场内部运营
- 不向任何第三方提供
- 不在任何公开内容中出现客户的完整姓名和联系方式
- 客户照片用于宣传前必须获得授权

### 5.3 品牌内容的发布底线

| 不做 | 说明 |
|:---|:---|
| 不摆拍、不用剧本、不讲假话 | 客户一眼能看出是不是演的 |
| 不提前吹嘘未完成的事 | 核心层还没建好时，不在内容里暗示"我们有生态种养" |
| 不发与农场无关的内容 | 账号定位必须清晰 |

## 第六部分：执行建议

### 6.1 从哪开始

**第一批（本周内启动，零成本）：**
1. "今天农场"每日记录（O01）——每天拍一张照片发社群。一个人30秒就能完成
2. 内容提交流程（周一上午各板块发计划）——建立习惯

**第二批（第1个月内）：**
3. 农场日记（O03）——每周1条，运营卫星负责人到岗后的核心产出
4. 内容数据追踪（O02）——每周汇总各平台数据

**第三批（第2-3个月）：**
5. 经营月报（O05/O06）——从第3个月开始编制（需要积累足够数据）
6. 手机短视频教学——教各板块主理人如何更好地自己产出内容

### 6.2 运营卫星公开化的特殊节奏

运营卫星的公开化节奏不取决于自己，而取决于其他板块的配合程度。

- 如果各板块按时供稿 → 内容日历顺利运转
- 如果各板块供稿不积极 → 运营卫星需要"追着要素材" → 这是启动阶段最可能出现的问题

**应对**：前3个月运营卫星负责人不要追求"内容多"，追求"内容持续"。即使每周只发1条，也比发3条断2周好。

| 模式 | 适配工作项数 | 说明 |
