# 客户数据管理方案（CRM落地设计）

> **性质**：策略设计（为Hermes CRM模块提供数据结构与业务逻辑）
> **后续动作**：方案确定后，由言渊将本方案转化为Hermes CRM帽的Skill配置
> **核心目标**：在Hermes体系内建立一套完整的客户数据管理机制，覆盖数据采集、存储、查询、分析、预警全链路
> **关联文件**：G-03客户信息管理流程（SOP层）、18.社群与会员系统搭建方案、20.会员裂变机制

## 一、CRM在Hermes中的位置

```
Hermes（调度层）
  │
  ├── 🧠 CEO帽     ← 调取CRM数据分析战略
  ├── 🔧 COO帽     ← 调取CRM数据优化服务
  ├── 👥 CRM帽     ← 直接管理客户数据（本方案的核心）
  ├── 📱 Content帽 ← 调取CRM数据做精准内容
  └── 💰 Finance帽 ← 调取CRM数据分析客户价值

CRM帽的核心职责：
  1. 维护客户数据库（增删改查）
  2. 自动识别关键节点（生日/沉睡/流失）
  3. 生成客户分析报告（日报/月报）
  4. 配合其他帽子提供客户数据支持
```

客户数据统一存储在 Obsidian 知识库中：

## 二、客户数据模型

### 2.1 客户主表字段定义

每条客户记录包含以下字段：

| 字段 | 类型 | 必填 | 填写方式 | 说明 |
|:---|:---|:---:|:---|:---|
| 客户ID | 自动编号 | 是 | 系统生成 | C0001格式，按首次到店顺序递增 |
| 姓名/昵称 | 文本 | 是 | 手动录入 | 客户允许的称呼 |
| 手机号 | 数字 | 是 | 手动录入 | 用于核销和活动通知 |
| 微信 | 文本 | 否 | 手动录入 | 如客户允许添加微信 |
| 首次来源 | 单选 | 是 | 选择 | 自然到店/社群/美团/小红书/B端合作/会员推荐/其他 |
| 首次到店日期 | 日期 | 是 | 系统记录 | 首次消费日期 |
| 最近到店日期 | 日期 | 是 | 自动更新 | 每次消费后更新 |
| 累计到店次数 | 数字 | 是 | 自动累计 | 每次消费+1 |
| 累计消费总额 | 数字 | 是 | 自动累计 | 所有消费金额加总 |
| 会员等级 | 单选 | 是 | 手动设置 | 普通客户/储值会员/年卡会员/长搭会员 |
| 人群标签 | 多选 | 否 | 手动标注 | 见标签体系 |
| 兴趣标签 | 多选 | 否 | 手动标注 | 见标签体系 |
| 价值标签 | 自动 | 是 | 系统计算 | 见标签体系 |
| 客户状态 | 单选 | 是 | 自动+手动 | 活跃/沉睡/流失/已删除 |
| 备注 | 文本 | 否 | 手动录入 | 特殊需求、重要事件 |

### 2.2 消费流水字段定义

每条消费记录包含：

| 字段 | 填写方式 | 说明 |
|:---|:---|:---|
| 日期 | 自动 | 消费发生的日期 |
| 客户ID | 手动选择 | 关联客户主表 |
| 消费板块 | 选择 | 引擎A餐饮/引擎B露营/核心层采摘/自然手作课程/其他 |
| 消费项目 | 文本 | 具体消费内容 |
| 金额 | 数字 | 实付金额 |
| 支付方式 | 选择 | 微信/支付宝/现金/储值余额/会员权益抵扣 |
| 记录人 | 自动 | 录入该记录的员工 |

### 2.3 互动记录字段定义

| 字段 | 填写方式 | 说明 |
|:---|:---|:---|
| 日期 | 自动 | 互动发生的日期 |
| 客户ID | 手动选择 | 关联客户主表 |
| 互动类型 | 选择 | 社群发言/投诉/建议/活动参与/推荐新客/回访/其他 |
| 内容摘要 | 文本 | 简要描述互动内容 |
| 跟进状态 | 选择 | 无需跟进/跟进中/已闭环 |
| 记录人 | 自动 | 录入该记录的员工 |

## 三、标签体系

### 3.1 人群标签（反映客户是谁）

- 亲子家庭（有12岁以下儿童）
- 年轻情侣/朋友（18-35岁）
- 中老年（55岁以上）
- 企业团建
- B端渠道合作

### 3.2 兴趣标签（反映客户喜欢什么）

美食类
- 火锅爱好者 / 烧烤爱好者 / 柴火灶爱好者
- 面包窑爱好者

露营类
- 自带装备露营 / 装备租赁露营 / 长搭露营

体验类
- 采摘爱好者 / 手作爱好者 / 自然教育参与者

内容类
- 拍照打卡型 / 内容创作者 / 社群活跃分子

### 3.3 价值标签（系统自动计算）

| 标签 | 计算规则 | 说明 |
|:---|:---|:---|
| 高价值客户 | 年消费≥3000元或月均到店≥2次 | 需一对一维护 |
| 中价值客户 | 年消费1000-2999元 | 常规维护 |
| 潜力客户 | 累计到店≤2次但消费意向强 | 重点转化 |
| 传播者 | 推荐新客≥3人或社群活跃 | 品牌口碑资产 |
| 沉睡客户 | 30-89天未到店 | 需唤醒 |
| 流失客户 | 90天以上未到店 | 需挽回 |

## 四、数据采集流程

### 4.1 新客采集

新客到店后24小时内，运营卫星在Hermes中完成以下操作：

```
1. 在客户主表中新建一条记录
2. 填写：姓名/昵称、手机号、首次来源
3. 标注人群标签（根据肉眼判断：一家三口→亲子家庭）
4. 系统自动生成客户ID和首次到店日期
```

**采集时机**（三选一即可，不需要专门打断客户）：

| 板块 | 最佳采集时机 | 话术参考 |
|:---|:---|:---|
| 引擎A点餐 | 点餐时报手机号核销时 | "我记一下您的信息，下次来不用再报了" |
| 引擎B入住 | 办理入住登记时 | 入住登记表自带手机号 |
| 社群入群 | 扫码入群时 | 微信群欢迎语自动引导填写 |

### 4.2 消费记录采集

```
每笔消费结账后，各板块主理人在Hermes中录入：

引擎A：客户ID + 消费项目 + 金额
引擎B：客户ID + 消费项目 + 金额（含房费+租赁+附加）
核心层：客户ID + 采摘品种 + 金额
自然手作：客户ID + 课程名称 + 金额

系统自动更新客户主表中的：
- 最近到店日期
- 累计到店次数
- 累计消费总额
- 价值标签（根据最新数据重新计算）
```

### 4.3 标签维护

| 场景 | 操作 | 负责人 |
|:---|:---|:---|
| 观察到客户行为 | 手动添加兴趣标签 | 运营卫星 |
| 客户到店满5次 | 关注是否可推储值会员 | 运营卫星 |
| 客户消费变化 | 更新价值标签 | 系统自动 |
| 标签错误 | 手动修正 | 运营卫星 |

## 五、数据查询与使用

### 5.1 日常查询场景

Hermes CRM帽支持以下查询（自然语言输入即可）：

| 使用场景 | 查询示例 |
|:---|:---|
| 客户到店前准备 | "查一下张三上次来是什么时候，吃了什么" |
| 沉睡客户回访 | "列出30天未到店的亲子家庭客户" |
| 营销推送 | "筛选有露营兴趣标记的客户" |
| 活动定向邀请 | "找出最近30天到店的储值会员" |
| 客户价值分析 | "年消费超过2000元的客户有哪些" |

### 5.2 每日自动简报

每天早8:00，Hermes CRM帽自动生成当日简报：

```
【CRM今日提醒】
━━━━━━━━━━━━━━━━
■ 今日生日客户：李四（C0023）、王五（C0089）
  → 建议发送生日祝福+赠礼提醒

■ 沉睡客户预警（30天未到店）：12人
  → 建议本周安排回访

■ 流失客户预警（90天未到店）：5人
  → 建议言渊评估是否需要挽回

■ 今日预约到店老客户：3人
  → 张三月日（C0015）上次消费328元/亲子家庭
  → 建议：推荐本月新上的柴火灶套餐
━━━━━━━━━━━━━━━━
```

### 5.3 月度分析报告

每月1日，Hermes CRM帽自动生成上月的客户分析报告，包含：

```
1. 本月新增客户数（按来源渠道分类）
2. 本月活跃客户数（有过消费的客户）
3. 客户到店频次分布（1次/2-3次/4次以上）
4. 复购率（本月有过消费的老客户占比）
5. 沉睡客户数和流失客户数
6. 会员增长情况（新增储值/年卡/长搭）
7. 各板块客户交叉消费率（吃了饭→也住了宿的比例）
8. 客户价值分布（高/中/潜力/沉睡/流失占比）
9. 本月建议（根据数据给出的策略建议）
```

## 六、自动化规则

### 6.1 触发条件与自动动作

| 触发条件 | 自动动作 | 通知对象 |
|:---|:---|:---|
| 客户生日当天 | 生成生日提醒+建议赠送内容 | 运营卫星 |
| 客户30天未到店 | 客户状态→沉睡，加入唤醒列表 | 运营卫星 |
| 客户90天未到店 | 客户状态→流失，加入挽回列表 | 言渊 |
| 客户累计到店5次未储值 | 生成转化建议 | 运营卫星 |
| 客户推荐新客到店 | 在原客户档案中+1推荐计数 | 自动记录 |
| 客户投诉处理完成 | 互动记录状态→已闭环 | 运营卫星 |
| 客户储值余额低于100元 | 生成续费提醒 | 运营卫星 |

### 6.2 隐私保护与数据安全

1. 客户数据仅存储在本地Obsidian知识库中，不上传任何云端
2. 客户手机号字段默认脱敏显示（138****1234）
3. 客户要求删除数据时，24小时内从主表和流水中彻底删除
4. 任何人不得将客户数据导出到CRM系统之外的任何位置
5. 违反数据安全的行为视为严重违纪

## 九、分阶段实施路径

### 第一阶段：基础搭建（第1个月）

- 在Obsidian中建立CRM目录和四个核心文件
- 定义客户主表的字段和格式
- 启动新客登记（从即日起的新客户开始记录）
- 历史客户数据暂不追溯（存量客户遇到时补录）

**交付标准**：每日新增客户已登记，消费记录已录入

### 第二阶段：功能完善（第2-3个月）

- 消费流水和互动记录开始积累
- 标签体系在实际使用中调整优化
- 每日简报逻辑跑通
- Hermes能回答基本的客户查询

**交付标准**：CRM数据可支撑晨会和日常运营

### 第三阶段：分析能力（第4-6个月）

- 积累足够数据后启动月度分析报告
- 沉睡/流失预警机制实际运行
- 客户分群营销开始应用
- 各板块交叉消费分析支持经营决策

**交付标准**：CRM数据驱动经营决策
