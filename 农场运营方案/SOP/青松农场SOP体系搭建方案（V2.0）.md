## 一、SOP设计原则

### 1.1 农场SOP的底层逻辑

农场跟工厂、餐厅、咖啡馆最大的区别是——**它的节奏不由人决定，由自然节律决定**。

工厂的SOP可以365天不变。农场的SOP必须跟着节气走：3月的工作和12月的工作完全不同。一套不变的SOP在春季指导不了春播，在冬季也阻挡不了停炉。

因此农场SOP的设计不是以"岗位任务"为组织方式，而是以**"农场的呼吸节律"**为底层逻辑：

- 核心层的SOP按**生长周期**（播种期/生长期/采收期/休耕期）划分
- 引擎A的SOP按**季节**（夏季版/冬季版）划分
- 引擎B的SOP按**淡旺季**（旺季版/淡季版）划分
- 运营卫星和综合管理的SOP受季节影响小，按标准频次执行

### 1.2 六项核心设计原则

| 原则        | 含义                     | 在方案中的体现                   |
| :-------- | :--------------------- | :------------------------ |
| **季节适配**  | 每条SOP标注适用季节，季节不同流程不同   | 核心层4条按生长阶段分；引擎A/B分季节版本    |
| **AI内嵌**  | Hermes是SOP的执行界面，不是独立工具 | 每条SOP标注AI接口和AI提醒；G-06完整设计 |
| **替代人机制** | 3人团队下任何一个人请假，流程不能断     | 每条SOP标注第一/第二顺位替代人         |
| **跨板块联动** | 客户体验是跨板块的，SOP不能各写各的    | 增加G-04协作流程；每板块SOP标注协作触发点  |
| **客户意识**  | 不仅写做什么，还要让执行人知道客户此刻的感受 | 触点SOP的关键步骤旁标注客户状态         |
| **反馈回路**  | SOP不是写一次用三年，执行人必须有渠道改  | 增加G-05修订流程；文件头部版本记录       |
|           |                        |                           |

## 二、SOP编写标准

### 2.1 一条SOP的完整结构

```
[SOP编号] 板块-序号
[SOP名称] 一句话说清
[执行人]
[替代人] 执行人不在时的第一顺位和第二顺位
[执行时间] 频率/时段
[适用季节] 3月-11月 / 12月-2月 / 全年（附季节提示）
[前置条件] 开始前需要什么已就绪
[AI接口] 将执行结果录入Hermes的指令
[AI提醒] Hermes何时/如何触发此SOP

执行步骤：
  1. ____ [客户状态：（如适用，标注客户此时的感受）]
  2. ____
  3. ____
  （不超过7步，超过7步拆成两条）

验收标准：
  □ ____
  □ ____

异常处理：
  如果____，则____

跨板块协作：
  触发条件：____
  通知对象：____
  通知方式：____（Hermes自动通知/群内通知）

记录位置：____

版本记录：
  V1.0 | 2026-06-02 | 初版编写
```

### 2.2 优先级定义

| 优先级 | 定义 | 完成时限 |
|:---:|:---|:---:|
| P0 | 不做会出安全问题或客户流失 | 1个月内完成编写和执行 |
| P1 | 不做会影响运营效率或品质一致性 | 2-3个月内完成 |
| P2 | 做好了更好，不做也不致命 | 有余力时再做 |

## 五、SOP与Hermes（AI）的集成设计

### 5.1 核心定位

Hermes不是独立工具，是SOP的操作系统。

```
SOP手册 = 写流程的地方（静态知识库，存储在SOP文件夹中）
Hermes   = 执行流程的地方（动态执行界面，每天生成执行清单）

执行人不需要同时打开SOP手册和Hermes。
言渊在SOP手册中编写和修订SOP，Hermes自动提取执行节点推送给执行人。
```

### 5.2 Hermes在每条SOP中的角色

| SOP类型 | Hermes做什么 | 执行人做什么 |
|:---|:---|:---|
| 日常执行型（开档/收档/巡检） | 按时间推送执行提醒；提供检查清单；记录完成状态 | 按清单执行，在Hermes中打钩确认 |
| 事件触发型（投诉/入住/团建接待） | 触发条件满足时推送SOP入口 | 打开推送，按SOP执行，记录结果 |
| 周期记录型（农事日志/数据汇总） | 定时推送填写提醒；提供上期数据参考 | 填写数据，提交后自动存档 |
| 跨板块协调型 | 执行人标记完成后自动通知下一环节负责人 | 执行完成后标记，不需要自己发消息 |

### 5.3 Hermes每日SOP推送示例

```
【6月2日 周二 晴 28度】

今日重点：
  核心层：玉米进入抽穗期，重点检查浇水（C-02）
  引擎A：有2组散客预订午餐，确认备料（A-01）
  运营卫星：下午2点前完成洗手间深度清洁（O-01）

今日提醒：
  [自动] 核心层C-02：今日需施酵素肥，用量已在系统中计算
  [自动] 上周四投诉的客户已到48小时回访窗口，需回访（O-05）

今日预约：
  10:00 自然教育引流课 已报名6人（含3个家庭）
    手作主理人：H-01课前准备
    引擎A：确认这3个家庭是否有用餐需求（跨板块协作触发）
```

### 5.4 Hermes-SOP集成规则

```
规则一：SOP是静态知识库，Hermes是动态执行界面
  言渊维护SOP文件，Hermes从中提取执行节点，生成每日执行清单
  执行人不需要去翻SOP文件夹——Hermes会推送今天需要做的SOP

规则二：执行结果自动回流
  每条SOP执行完成后，执行人在Hermes中标记完成
  Hermes记录完成时间、异常情况、执行人备注
  月度复盘时，Hermes自动生成SOP执行率报告

规则三：SOP修订闭环
  执行人发现SOP不合理时，在Hermes中提交修订建议
  言渊审阅后确认修订，Hermes自动更新SOP文件并推送更新通知

规则四：新人上手路径
  新员工入职第一天，Hermes推送G-01入职流程
  完成后逐步开放对应SOP权限——不会一次性看到所有SOP
```
