## 第一部分：为什么要公开化

### 1.1 公开化的底层逻辑

农场建设公开化的本质不是"让客人来帮忙干活"，而是：

> **把农场必须做的事，变成与客人建立关系的机会。**

农场每天都在发生大量"有内容、有画面、有故事"的环节——菜在长、鸡在跑、面包在窑炉里烤、灯串在松林里挂。过去这些环节只在"后场"发生，客人看不到。公开化的目的就是把这些环节拉到"前台"，让客人看见、触摸、参与。

### 1.2 公开化的三大价值

| 价值 | 说明 | 对应板块的典型体现 |
|:---|:---|:---|
| **建立信任** | 让客户亲眼看到、亲手摸到农场的真实运作 | 核心层：堆肥制作、酵素发酵、鸡群散养 |
| **放大传播** | 每个参与环节都是客户的"朋友圈素材" | 引擎A：面包出炉、柴火灶冒气、大席摆满 |
| **创造归属** | 客户有了"我参与过""我有印记"的情感连接 | 引擎B：共建的木平台、认领的松树、刻名的篝火台 |

### 1.3 各板块的公开化侧重

| 板块 | 核心公开化价值 | 最适合的模式 | 公开化优先级 |
|:---|:---|:---:|:---:|
| 核心层（生态种养） | 信任建设 | 课程化+劳动换薪 | ★★★★★ |
| 引擎A（餐饮） | 传播放大 | 课程化+劳动换薪 | ★★★★☆ |
| 引擎B（露营住宿） | 归属创造 | 共建化+课程化 | ★★★★☆ |
| 自然手作卫星 | 传播裂变（课程已公开） | 课程化（传播优化） | ★★★☆☆ |
| 运营卫星 | 向内透明+向外品牌 | 内容化+财务透明 | ★★★☆☆ |

### 1.4 公开化的底线——什么时候不做

评估一项工作是否适合公开化，先过以下三道红线：

| 红线 | 说明 | 被拦截的工作示例 |
|:---|:---|:---|
| **安全风险** | 涉及专业操作/动物健康/食品安全的工作不开放 | C16鸡群健康巡查、C17鸡舍清洁消毒、A06生肉处理环节 |
| **效率影响** | 客户参与会显著降低生产效率的工作不开放 | C06病虫害防治高峰期、引擎A午晚高峰全时段 |
| **体验破坏** | 公开后会影响其他客户体验的工作不开放 | 引擎B深夜施工、引擎A高峰期厨房开放 |

## 第二部分：五种互动模式总览

### 2.1 模式定义速查

| 模式 | 定义 | 本质 | 适合什么工作 | 客户心理 |
|:---|:---|:---|:---|:---|
| 课程化 | 将有知识含量的工作设计为有结构的体验活动 | 把劳动包装为教育产品 | 有原理可讲、有步骤可演示、有成果可带走 | "学到了+带走了" |
| 共建化 | 将需要集中力量完成的工作设计为集体活动 | 把建设包装为集体事件 | 需要多人协作、做完有明确视觉成果 | "有我的印记" |
| 劳动换薪 | 将日常重复的轻体力工作开放给客户 | 把维护开放为轻体验 | 门槛低、做错了也不影响生产 | "赚了杯啤酒" |
| 认领化 | 将可分割的资产开放给客户标记为"我的" | 把资产分割为个人专属 | 有物理边界、可挂标识牌 | "这是我的" |
| 技能传承 | 识别客户擅长而农场需要的技能并发起交换 | 客人擅长的转为农场需要的 | 农场不擅长而客人可能精通 | "我的本事有用" |

### 2.2 决策树（选择模式的判断流程）

```
这项工作能通过三道红线吗？（安全/效率/体验）
  +-- 不能 --> 不做
  +-- 能
        +-- 有知识含量吗？
        |   +-- 有 --> 课程化（最安全、有收入、可做品牌）
        |   +-- 没有
        |         +-- 需要集中力量才能完成吗？
        |         |   +-- 是 --> 共建化（低成本建设+深度关系）
        |         |   +-- 否
        |         |         +-- 客人比我们更擅长？
        |         |         |   +-- 是 --> 技能传承
        |         |         |   +-- 否
        |         |         |         +-- 是日常重复的轻活吗？
        |         |         |         |   +-- 是 --> 劳动换薪
        |         |         |         |   +-- 否
        |         |         |         |         +-- 是可分割、可标记的资产吗？
        |         |         |         |         |   +-- 是 --> 认领化
        |         |         |         |         |   +-- 否 --> 不做
```

| 板块 | 课程化 | 共建化 | 劳动换薪 | 认领化 | 技能传承 | 不做 |

| 核心层（24项） | 15 | 5 | 8 | 3 | 3 | 3 |

## 第四部分：执行体系

> 总册的任务：将5个板块分册中的执行流程统合成一套农场级的运营体系。本部分不重复各板块的个体执行细节（那些在各分册中已写），而是聚焦跨板块的协同、节奏、传播和数据。

### 4.1 农场公开化的整体节奏设计

5个板块的公开化活动不能各自为政、撞期抢人，也不能同时全部上线导致团队崩溃。需要设计一个"自然节拍"——让公开化融入农场的日常呼吸节奏。

#### 4.1.1 日节奏——每天自然发生的公开化

不是每天都需要搞活动，而是每天都有"后台变前台"的意识。

| 时段 | 板块 | 天然可公开的环节 | 公开形式 |
|:---|:---|:---|:---|
| 7:00-8:00 | 核心层 | 喂鸡、捡蛋、菜地浇水 | 劳动换薪小黑板（当天写"今日可帮忙：喂鸡，10分钟，5元"） |
| 8:00-9:00 | 引擎A | 面包窑生火、面团入炉 | 朋友圈小视频（运营卫星顺手拍30秒"面包在长大"） |
| 9:00-11:00 | 多板块 | 课程化/共建化活动高峰期 | 按预约执行 |
| 11:00-13:00 | 引擎A | 柴火灶冒烟、大席开席 | 现场直播感内容 |
| 14:00-16:00 | 自然手作 | 手作课程 | 拍照记录 |
| 16:00-18:00 | 引擎B | 营地布置、篝火台搭木柴 | 共建/劳动换薪 |
| 18:00-20:00 | 引擎A/B | 面包出炉、篝火点燃 | 最出片时刻 |

**关键原则**：日节奏不是排班表，而是"在什么时间做什么事最自然、最出片"。运营卫星根据日节奏规划当天的内容捕捉计划。

#### 4.1.2 周节奏——每周固定的公开化项目

| 星期 | 上午（9:00-11:00） | 下午（14:00-16:00） | 运营卫星内容产出 |
|:---|:---|:---|:---|
| 周一 | 休园日 | 休园日 | 上周总结+本周预告 |
| 周二 | 核心层：堆肥/酵素课 | 引擎A：面包烘焙课 | 周二上午的课拍图→周三发 |
| 周三 | 引擎B：营地建设日 | 自然手作：当周手作课 | 周三建设进展→周四发 |
| 周四 | 核心层：种植课 | 引擎A：大席备料开放 | 周末活动预告 |
| 周五 | 自由活动日（承办定制） | 场地布置+准备 | 周末预热 |
| 周六 | 大活动日（见下方月历） | 大活动日 | 现场直播 |
| 周日 | 大活动日 | 大活动日 | 现场快剪 |

**建立"每周固定课表"**：5个板块协商确定每周固定开课的时间和主题（比如每周二上午10点是堆肥课、每周四下午2点是插秧/播种课），让老会员形成"周二来农场上课"的习惯。

#### 4.1.3 月节奏——每月一次的主题事件

每个月至少安排一次**跨板块联动的大事件**，作为当月公开化的高潮：

| 月份 | 主题事件 | 涉及板块 | 公开化模式 |
|:---|:---|:---|:---|
| 1月 | 冬修·共建月：修鸡舍+搭暖棚 | 核心层+引擎B | 共建化为主 |
| 2月 | 春播节：育苗+播种启动 | 核心层+自然手作 | 课程化+劳动换薪 |
| 3月 | 松林苏醒：篝火台共建+早春风筝 | 引擎B+自然手作 | 共建化+课程化 |
| 4月 | 青松春宴：野菜宴+松林野餐季开启 | 引擎A+核心层 | 课程化+认领化 |
| 5月 | 小麦熟了：割麦+打麦+磨面 | 核心层+引擎A | 课程化+劳动换薪 |
| 6月 | 仲夏夜：面包窑开放夜+露营季 | 引擎A+引擎B | 课程化+共建化 |
| 7月 | 掰玉米大赛：采收+玉米宴+玉米手作 | 核心层+引擎A+自然手作 | 课程化+劳动换薪 |

| 11月 | 堆肥月：全年堆肥巡礼+土壤检测开放 | 核心层 | 课程化+劳动换薪 |
| 12月 | 年终感恩：共建成果展示+认领人回访+证书颁发 | 全板块 | 全模式 |

**节奏设计原则**：
- 每个月的主题事件紧扣当季农事——不额外造节，只把"本来就在做的事"放大
- 一个主题事件联动至少2个板块，让客人一次体验多面
- 提前30天确定下月主题，给运营卫星充足的准备和预热时间

### 4.2 跨板块协同机制

#### 4.2.1 信息共享——每周15分钟"公开化站会"

| 参与者 | 时间 | 地点 | 议程 |
|:---|:---|:---|:---|
| 各板块主理人+运营卫星+言渊 | 每周一上午10:00 | 引擎A面包窑旁（非会议室） | ①本周各板块有哪些必做工作有公开化潜力（3分钟）②已预约的活动进展（5分钟）③需要协调的资源（3分钟）④内容产出计划确认（4分钟） |

**核心目标**：不让公开化变成运营卫星一个人的事，而是每个板块主理人在做日常工作时顺手就能想到"这个可以公开"。

#### 4.2.2 跨板块活动的"主承办"机制

当一个主题事件涉及多个板块时，采用"主承办制"：

| 角色 | 职责 | 承担者 |
|:---|:---|:---|
| 主办方 | 确定活动流程、现场总指挥、核心内容交付 | 与主题最相关的板块主理人 |
| 协办方 | 提供场地/物资/人员支持 | 其他涉及板块 |
| 运营卫星 | 招募文案、拍摄、传播、客户对接 | 运营卫星 |

**示例——7月掰玉米大赛**：
- 主办方：核心层（种玉米的主管负责活动设计+现场指挥）
- 协办方：引擎A（提供玉米宴加工）+ 自然手作（提供玉米皮手作）
- 运营卫星：一个主题文案+三个板块分别招募

#### 4.2.3 资源冲突处理原则

| 常见冲突 | 处理原则 |
|:---|:---|
| 两个板块要同一时间段用同一块场地 | 按"可替代性"判决——可改期的板块改期，不可改期的优先（如面包窑烤制时间不可调） |
| 人手不够同时支持两场活动 | 错开时段，或合并为一场多板块联动活动 |
| 一天内活动太多导致农场拥挤 | 设定每日上限：工作日不超过1场付费活动，周末不超过3场 |
| 客户同时报名了冲突的活动 | 运营卫星主动协调，优先保留与农场主线最相关的活动 |

### 4.3 内容传播矩阵——公开化的二次传播引擎

公开化活动的现场效果是"一次传播"，而活动后的内容扩散是"二次传播"，后者才是公开化的真正杠杆。

#### 4.3.1 内容来源与分工

| 内容类型 | 来源 | 谁产出 | 发布渠道 | 频率 |
|:---|:---|:---|:---|:---|
| 预告类 | 下周活动安排 | 运营卫星 | 社群+朋友圈 | 每周1条 |

#### 4.4.3 季度深度复盘

每季度一次，言渊+各板块主理人+运营卫星一起，用2小时做深度复盘。重点讨论：

1. 上个季度公开化整体效果是否达到预期？财务上赚了吗？品牌上有帮助吗？
2. 哪个板块的公开化效果最好？为什么？能不能复制到其他板块？
3. 哪个板块的公开化效果最差？要不要调整模式还是直接停掉？
4. 有没有"意外的惊喜"——某个没预期会火的活动反而火了？为什么？
5. 客户的真实反馈是什么？（不是满意度评分，而是客户说了什么话）
6. 农忙季要不要暂停公开化？什么条件下恢复？

**关键问题**：每季度回答一次——"公开化这件事，值得继续做吗？"如果答案是"值"，那就继续迭代。如果答案是"不值得"，就收缩或调整。

### 5.1 全农场风险分级总表

按风险从低到高，将所有板块的公开化活动统一分级：

| 等级 | 定义 | 涉及活动范围 | 典型代表 | 管控策略 |
|:---:|:---|:---|:---|:---|
| **L1 低风险** | 几乎无物理风险，所有年龄段可参与 | 观察类、听讲类、轻手作类 | 核心层：喂鸡、捡蛋、种子收集、酵素制作；引擎A：面包出炉观摩、大席观摩；引擎B：营地参观、篝火观看；自然手作：大部分手作课程 | 标准安全告知+提供手套/围裙即可 |
| **L2 中风险** | 有轻体力劳动或简单工具使用 | 动手耕作类、轻加工类 | 核心层：除草、叶菜/根茎采收、堆肥翻堆、翻地做垄；引擎A：食材预处理、面包/披萨实操、野餐篮打包；引擎B：标识制作、灯串布置协助、布置协助 | 安全告知+工具使用示范+主管在场+限定参与人数 |
| **L3 较高风险** | 涉及锐利工具、较大体力支出或高温环境 | 收割类、建造类、热加工类 | 核心层：搭架、粮食采收、鸡舍修缮；引擎A：生火、劈柴、窑炉操作；引擎B：木工搭建、小院建造、篝火台搭建 | 仅限成人+1对3以内指导+配备急救箱+签署纸质免责协议 |

## 第六部分：落地路线图

> 公开化不是一项"额外工作"，而是融入农场日常的思维方式。本路线图按三阶段推进，每个阶段有明确的核心动作、资源投入和验收标准。

### 6.1 第一阶段：启动期（第1-30天）

**目标**：用最小的成本验证公开化模式是否可行，跑通一个完整闭环。

#### 第1周：准备

| 动作 | 负责人 | 产出 |
|:---|:---|:---|
| 各板块主理人通读本总册+对应分册，了解公开化的五种模式和底线 | 全团队 | 团队认知对齐 |
| 运营卫星准备工具：活动记录表、免责协议模板、招募文案模板 | 运营卫星 | 模板就位 |
| 各板块确定"第一个公开化项目" | 各板块主理人 | 每个板块选1个项目 |
| 在核心区入口处放置一块"今日可帮忙"小黑板 | 核心层+运营卫星 | 劳动换薪小黑板就位 |

**各板块的第一个项目建议**：
- **核心层**：劳动换薪小黑板（先放"喂鸡"和"捡蛋"，零成本）
- **引擎A**：面包出炉时的"面包分享课"（面包本来就是烤的，多做一个流程即可公开）
- **引擎B**：营位搭建的"共建邀请"（搭一个营位时邀请客人一起动手）
- **自然手作**：现有课程中选一个最有特色的，在课中加入"后台故事"环节（如手作老师讲这个材料的来源）
- **运营卫星**：开始每天1条"后台内容"（拍工作日常发社群）

#### 第2-3周：试跑

| 动作 | 负责人 | 验收标准 |
|:---|:---|:---|
| 核心层小黑板试运行，记录每天有多少人问、多少人参加 | 核心层主管 | 每天至少1人参与 |
| 引擎A选一个非高峰时段（如下午3点）做一次面包体验课招募 | 引擎A+运营卫星 | 招募发出后24小时内有至少3人报名 |
| 运营卫星发出第一篇"后台"内容 | 运营卫星 | 曝光量大于500 |
| 首次"公开化站会" | 全团队 | 会议记录存档 |

**注意事项**：试跑阶段不追求完美，重要的是跑通流程——从"发现工作"->"设计模式"->"发布招募"->"现场执行"->"收尾传播"->"记录复盘"，每个环节都有人知道怎么做。

#### 第4周：回顾与调整

| 动作 | 产出 |
|:---|:---|
| 汇总第一个月的公开化数据 | 活动场次、参与人数、收入、传播数据 |
| 团队回顾：什么做对了？什么做错了？什么流程不顺畅？ | 改进清单 |
| 确定第二个月的公开化计划 | 下月日历+至少确定2个跨板块联动活动 |

**启动期验收标准（全部完成即进入第二阶段）**：
- [ ] 至少2个板块各跑通了1次完整的公开化活动
- [ ] 劳动换薪小黑板日常运营中
- [ ] 运营卫星每日内容产出机制已建立
- [ ] 团队所有成员理解五种模式并能判断什么工作适合什么模式
- [ ] 第一次月度公开化月报完成

### 6.2 第二阶段：扩展期（第31-90天）

**目标**：从单点验证走向常态化运营，建立"按月排期、按周执行"的节奏。

#### 核心动作

| 动作 | 时间 | 说明 |
|:---|:---|:---|
| 各板块增加到至少3个常态公开化项目 | 第2个月 | 每个板块至少3项工作常态化公开 |
| 推出第一次跨板块联动活动 | 第2个月 | 参考月节奏表选一个适合当月的主题 |
| 认领化产品正式上线 | 第2个月 | 从最容易的认领品起步（认领果树/认领鸡） |
| 建立每周固定课表 | 第2个月下旬 | 如"每周二上午堆肥课、每周四下午播种课" |
| 各板块内容SOP形成习惯 | 第2-3个月 | 每场活动后的"30分钟出图"成为肌肉记忆 |
| 技能传承开始尝试第一个邀请 | 第3个月 | 识别擅长某项技能的客户，发起1次交换 |
| 农场公开化内容产出量达到稳定频率 | 第3个月 | 每周3-5条内容+每月1-2篇深度文章 |

#### 扩展期验收标准

- [ ] 5个板块全部有日常公开化活动在运行
- [ ] 劳动换薪达到每周>=3次参与
- [ ] 课程化活动每月>=4场，单场>=4人
- [ ] 至少1次跨板块联动活动成功举办
- [ ] 认领化产品上线且有至少5位认领人
- [ ] 运营卫星内容矩阵建立：社群+小红书+朋友圈持续更新
- [ ] 月度公开化直接收入>=1,000元

### 6.3 第三阶段：成熟期（第91天-1年）

**目标**：公开化成为农场的日常表达方式，客户养成"上农场"的习惯，公开化收入和传播效应自运转。

#### 核心动作

| 动作 | 时间 | 说明 |
|:---|:---|:---|
| 固定课表+月历稳定运行 | 第4个月起 | 客户能提前一个月知道农场下个月有哪些活动 |
| 技能传承平台化 | 第4-5个月 | 在社群中发起"你有什么技能想交换"的话题 |
| 共建化成果展示区建成 | 第5个月 | 农场内的共建成果（铭牌/签名墙/共建说明牌）成为一道风景 |
| 年度大型公开活动规划 | 第6个月 | 秋季丰收节/年终感恩日等大事件 |
| 公开化内容的品牌化 | 第6个月起 | "青松农场日常"成为有辨识度的内容IP |
| 公开化制度文档化 | 第9个月 | 所有流程沉淀为标准操作手册，为团队扩编做准备 |
| 半年度深度评估 | 第6个月 | 投入产出比分析，决定下半年方向 |

#### 成熟期核心指标

| 指标 | 第6个月目标 | 第12个月目标 |
|:---|:---:|:---:|
| 月度公开化活动场次 | >=15场 | >=25场 |
| 月度参与总人次 | >=150人次 | >=300人次 |
| 月度公开化直接收入 | >=3,000元 | >=8,000元 |
| 月度公开化间接收入（联动消费） | >=8,000元 | >=20,000元 |
| 认领化产品续费率 | >=60% | >=70% |
| 内容月曝光量 | >=50万 | >=150万 |
| 劳动换薪小黑板月参与人次 | >=40人次 | >=80人次 |
| 客户自发传播率（客户发朋友圈/小红书的比例） | >=30% | >=50% |

### 6.4 什么时候放慢或停止

公开化不是越多越好。以下信号出现时，需要放慢节奏甚至暂停：

| 信号 | 判断标准 | 应对 |
|:---|:---|:---|
| 影响正常生产 | 公开化导致核心层种养产出明显下降 | 暂停该板块公开化，优先保障生产 |
| 客户投诉增多 | 客户抱怨"体验不好"、"太商业化"、"太多人了" | 减少活动场次，降低同时接待人数 |
| 团队疲劳 | 员工抱怨"整天搞活动没时间干正事" | 精简活动，保证每个活动都是精品而不是数量 |
| 财务不划算 | 公开化活动收入覆盖不了人力成本+材料成本 | 只有高传播价值的活动可以"亏钱做"，否则取消 |
| 安全事件 | 发生任何二级及以上安全事故 | 全面暂停，复盘后重新评估 |
