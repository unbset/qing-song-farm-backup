## 使用说明

运营卫星是所有板块中**最特殊的一个**——它不生产任何产品和体验，但所有产品和体验的顺畅运行都依赖它。它的工作方式是**协调多于执行**——多数事情不是自己干，是推动别人干。

| 维度   | 引擎/核心      | 运营卫星                   |
| :--- | :--------- | :--------------------- |
| 工作对象 | 客户/产品/土地   | **其他板块**（内部服务）         |
| 工作方式 | 直接执行       | **协调+监督+兜底**           |
| 成果   | 客户满意       | 其他板块能顺畅工作              |
| 考核   | 利润/客流量/转化率 | **制度执行率+异常处理时效+内部满意度** |

## 1. 定位与价值

**运营卫星是农场的中枢神经系统——不直接产生客户体验，但确保所有客户体验的顺畅运行。**

如果把整个农场比作一列火车：
- **核心**：燃料（生态种养）
- **引擎A/B**：动力轮（餐饮+住宿）
- **自然手作卫星**：车厢服务（课程+体验）
- **田园摄影卫星**：沿途风景记录（摄影）
- **运营卫星**：**铁轨+信号+调度**——没有它，其他板块跑不起来，或者跑起来会撞车

### 在星形结构中的精确位置

```
                  运营卫星（中枢）
                /     |     |      \
               ↓      ↓     ↓       ↓
            核心    引擎A   引擎B   自然手作
            (供料)  (餐饮) (住宿)   (课程)
               ↑      ↑     ↑       ↑
                \     |     |      /
                  田园摄影（增值服务）
```

运营卫星不向任何板块汇报——它服务所有板块，同时监督所有板块的统一标准和底线。

## 2. 职能清单与边界（做什么 & 不做什么）

### 2.1 六大职能

#### 职能一：公共环境管理（P0——不可缺失）

| 项目      | 内容              | 频率             | 方式                      |
| :------ | :-------------- | :------------- | :---------------------- |
| 停车场     | 地面平整、标识清晰、车辆引导  | 每日巡查           | 运营卫星巡查 → 发现 → 通知相关人员处理  |
| 公共厕所    | 清洁、洗手液/纸巾补充、无异味 | 每日巡查（周末高峰增加频次） | 运营卫星巡查 → 不合格当场清理（自己或协调） |
| 公共步道/松林 | 垃圾清理、枯枝清理、标识牌维护 | 每周2-3次         | 运营卫星巡查 → 通知引擎B或核心协助清理   |
| 垃圾桶     | 清空、清洗、不溢出       | 每日（周末增加频次）     | 运营卫星巡查 → 通知相关人员         |
| 公共休息区   | 桌椅整洁、遮阳/避雨设施完好  | 每周巡查           | 运营卫星巡查 → 报修             |

**核心原则**：运营卫星不是"自己干保洁"——是**建立巡查制度+发现问题+协调解决**。日常保洁工作可以由各板块分担（引擎A管自己周边、引擎B管露营区周边、公共区域由运营卫星协调排班）。

#### 职能二：品牌与内容管理（P0——已经确定）

已在岗位工作指导手册中定义，此处概述：
- 农场统一自媒体账号运营（内容审核、发布、数据追踪）
- 品牌调性标准制定（视觉风格、用语规范、对外口径）
- 审核各板块产出的内容，确保调性一致
- 月度汇总各板块内容数据
- 处理品牌危机事件

#### 职能三：安全与应急管理（P0——不可缺失）

| 项目 | 内容 | 频率 |
|:---|:---|:---|
| 急救箱 | 各板块急救箱配置检查、过期药品更换 | 每月检查一次 |
| 灭火器 | 位置检查、年检标签确认、压力表检查 | 每季度检查一次 |
| 防火巡查 | 松林防火重点区域巡查、用火区域安全监督 | 每周（秋冬干燥季每日） |
| 应急预案 | 火灾/受伤/食物中毒/恶劣天气——处理流程书面化 | 制定一次，每年更新 |
| 意外事件处理 | 客户受伤/设备故障/突发纠纷——第一时间到场协调 | 发生即启动 |

**保险策略**（由运营卫星统一管理、统一投保）：

| 险种 | 覆盖范围 | 保额建议 | 年费参考 | 优先级 | 备注 |
|:---|:---|:---:|:---:|:---:|:---|
| **公众责任险（场地险）** | 客户在农场场地范围内发生的意外伤害（含农事体验活动） | 每次事故≥100万 | 2,000-5,000元/年 | **P0——必须买** | 确认条款包含"农事体验""农业观光"类目。普通场地险可能不覆盖农具操作等农场特有风险 |
| **食品安全责任险** | 客户因食用农场提供的食品/饮品导致的食物中毒或健康损害 | 每次事故≥50万 | 1,000-3,000元/年 | **P0——必须买** | 覆盖引擎A的餐饮出品+窑炉面包+野餐篮+中心厨房零售。建议选择含"农业自产食材"条款的产品 |
| **雇主责任险** | 员工（含兼职）在工作期间发生的意外伤害 | 每人≥20万 | 500-1,500元/年 | **P0——必须买** | 覆盖厨师、帮工、种植养殖主管、自然手作主理人、运营卫星负责人等所有全职/兼职人员。正式员工到岗即投保 |

**投保原则**：
- 以上三险在同一家保险公司打包投保通常有折扣，建议找平安/太平洋/人保等大型保险公司询打包价
- 公众责任险+食品安全险可在同一保单下打包（统称"场所综合责任险"或"农业旅游综合险"）
- 投保前向保险经纪明确说明农场的业务范围：餐饮服务 + 户外露营 + 农事体验活动 + 儿童自然教育课程，要求保险公司书面确认覆盖范围
- 保单复印件存放在运营卫星档案中，所有板块主理人知悉保险范围
- 发生意外事件后，运营卫星负责第一时间联系保险公司报案（报案时效通常是事故发生48小时内）

**核心原则**：运营卫星负责**建立制度+定期检查+突发事件到场**，各板块负责**执行日常安全操作**（引擎A管厨房用火，引擎B管露营用火）。

#### 职能四：客户关系管理（CRM）（P1）

| 项目     | 内容                                   | 工具                    |
| :----- | :----------------------------------- | :-------------------- |
| 客户信息统一 | 姓名+联系方式+来源渠道+到店次数+消费记录+备注            | 初期：腾讯文档/飞书表格，逐步→CRM工具 |
| 客户标签   | 按来源/消费偏好/活跃度打标签——"露营客户""自然教育客户""高消费" | 同表                    |
| 交叉推荐   | 梳理"这个客户常来露营→可以推长搭""这个客户上自然课→可以推手作体验" | 运营卫星主动推送，各板块执行        |
| 老客户维护  | 生日问候、消费满X次送小礼物、季度回访                  | 运营卫星定期执行              |
| 客户投诉处理 | 统一接受投诉→分类→指定处理人→跟踪闭环                 | 运营卫星统一入口              |

**初期建议**：客户在50-100人量级时，一个表格+微信群就能管。关键不是工具，是**有一个人在主动维护客户关系这件事**——而不是等客户来找。

#### 职能五：线上零售与商城（P1）

| 项目 | 内容 |
|:---|:---|
| 产品范围 | 手作体验的零售产品（皂/驱蚊膏/松塔香等）+ 农场伴手礼 + 引擎A的窑烤面包（自提/囤货） |
| 销售渠道 | 初期：微信群+朋友圈直接下单 → 中期：小程序商城/微店 |
| 运营流程 | 各卫星供货 → 运营卫星上架销售+接单+安排配送/自提 → 各卫星按单生产 |
| 库存管理 | 运营卫星统一记录库存，各卫星生产后报数 |

**核心原则**：运营卫星是"销售渠道"，不是"生产方"。各板块负责做出好产品，运营卫星负责把它们卖出去。

#### 职能六：行政协调（兜底）

| 项目 | 内容 |
|:---|:---|:---|
| 资质维护 | 营业执照/食品经营许可证/卫生许可/消防检查等——到期提醒+办理 |
| 采购协调 | 各板块通用物资的统一采购（不是各买各的） |
| 排班协调 | 大型活动（四季庆典/运动会）时的全员排班 |
| 新员工入职/培训 | 基础制度培训（安全/品牌调性/服务标准） |
| 会议室/仓库/工具等公共资源管理 | 谁在用、什么时候还 |

### 2.2 明确不做什么

运营卫星的职能边界容易膨胀——"反正都要有人做→给运营卫星"。以下**明确不属于运营卫星**：

| 不属于运营卫星 | 理由 | 归谁 |
|:---|:---|:---|
| 各板块的具体业务决策 | 引擎A的菜单、引擎B的定价、自然教育的教案——运营卫星不干预 | 各板块主理人 |
| 各板块的日常运营执行 | 引擎A的厨师炒菜、引擎B的帮工收帐篷、自然手作老师带课 | 各板块执行 |
| 各板块的客户服务 | 客户的自然教育课程咨询由自然手作卫星直接回答（不是转到运营卫星再转回去） | 各板块直接服务 |
| 农场主/重要客户接待 | 言渊的客人由运营卫星协助，但不归运营卫星管 | 言渊直接负责 |

## 3. 人员配置与时间分配（1个人+言渊兼管怎么干活）

### 3.1 运营卫星负责人的一周时间分配建议

这是运营卫星最现实的问题——1个人（副手）要管6大职能，不可能平均用力。建议的时间分配：

| 时间占比 | 职能 | 说明 |
|:---|:---|:---|
| **25%** | 公共环境巡查 + 安全巡检 | 每天早晚各30分钟走一遍全场 + 发现问题追闭环 |
| **20%** | 品牌内容（统一账号+内容审核+发布） | 内容审核各板块提交的素材（每天20分钟）+ 统一账号内容制作+发布（每周半天） |
| **15%** | 线上零售（商城管理+接单+配送安排） | 处理订单、更新库存、安排配送（每天15-20分钟） |
| **15%** | 客户关系管理（信息更新+老客户维护+投诉处理） | 更新客户信息/回访老客户/处理投诉（每周半天集中处理） |
| **10%** | 行政协调（资质/采购/排班/公共资源） | 到期资质提醒+采购协调+活动排班（每周半天的行政时间） |
| **10%** | 各板块协调会（每日站会/每周例会） | 每天早15分钟站会对齐各板块当天安排 + 每周30分钟例会 |
| **5%** | 学习/优化/复盘 | 整理运营数据、优化流程、学习新工具 |

### 3.2 关键原则

| 原则 | 说明 |
|:---|:---|
| **不用自己干** | 巡查发现厕所不干净→不是运营卫星自己拿抹布擦→是通知负责该区域的人处理+跟进闭环 |
| **制度管人** | 建好制度（公共区域清洁标准/安全检查清单/客户信息录入格式）→各板块执行→运营卫星检查 |
| **先做P0，再扩P1** | 前3个月运营卫星的核心工作只是公共环境+安全+品牌内容。CRM和零售可以在P0跑稳后再加 |
| **言渊是后盾** | 运营卫星负责人处理不了的事（跨板块纠纷/预算审批/对外合作决策）→上报言渊拍板 |

## 4. 工作流程与接口

### 4.1 日常工作接口

| 时间 | 动作 | 参与人 | 内容 |
|:---|:---|:---|:---|
| 每天早8:30 | **10分钟站会** | 各板块主理人/代表（可线上） | 今天有什么安排？需要什么支持？有什么风险？ |
| 每天早晚各30分钟 | **全场巡查** | 运营卫星负责人 | 公共环境+安全巡检→发现→解决→记录 |
| 每周一 | **内容审核** | 运营卫星+各板块提交素材 | 各板块提交本周准备发布的内容→运营卫星审核→确认 |
| 每周五 | **客户数据更新** | 运营卫星负责人 | 更新本周新增客户信息+标记消费记录+下周回访计划 |
| 每月末 | **运营数据汇总** | 运营卫星负责人 → 言渊 | 客户数/到店频次/各板块营收/内容数据/异常事件 |
| 大型活动前 | **活动协调会** | 运营卫星组织+全体板块 | 分工+物资+时间节点——见四季庆典分析 |

### 4.2 "发现→解决→闭环"问题处理流程

公共环境巡查一定会发现问题（厕所纸没了/路上有垃圾/标识歪了）。处理流程：

```
发现（运营卫星巡查）
  ↓
记录（拍照+微信发到"运营群"+@负责人）
  ↓
处理（负责人安排或自己处理）
  ↓
反馈（处理完毕→群里回复"已处理"+发图）
  ↓
记录（运营卫星在问题记录表存档，追踪高频率问题）
```

**核心**：**不追责，追解决。** 公共区域脏了不是"谁弄脏的"的问题，是"谁清理"的问题。运营卫星不追责（那是各板块内部的事），只追踪"解决了吗"。

## 6. 考核标准

运营卫星是**保障中心**，不考核利润。考核以下三项：

### 指标一：问题发现到闭环的时效

| 项目 | 标准 |
|:---|:---|
| 公共环境问题从发现到解决 | 简单问题（垃圾桶满/厕所缺纸）≤1小时；复杂问题（设施损坏）≤48小时 |
| 客户投诉从接到到回复 | ≤2小时（高峰期≤30分钟） |
| 安全问题从发现到整改 | 严重（灭火器失效/电路隐患）≤24小时；一般≤1周 |

### 指标二：品牌内容执行率

| 项目 | 标准 |
|:---|:---|
| 各板块每周内容提交率 | ≥80%（不是每一篇都要按时交，但总体节奏不能断） |
| 统一账号每月发布频次 | 每月≥8条（每周2条，不追求量追求持续） |
| 品牌调性一致性 | 各板块对外发布的内容未经审核发出的比例≤5% |

### 指标三：客户数据完整度

| 项目 | 标准 |
|:---|:---|
| 到店客户的信息记录率 | ≥70%（不是每个客户都要记，但常客和消费客户要记） |
| 老客户（3次+到店）的生日/偏好信息完整度 | ≥90% |

## +1 多角色验证

### 角色A：运营卫星负责人（到岗第1周）

**体验**：到岗第一天，言渊说"运营卫星的职责就这些，你看看怎么管"——看到6大职能、一个人干、压力很大

**实际节奏建议**：
- 第1周：什么都不干，跟着各板块走一圈——认识人、认识场地、认识流程。**先理解再动**
- 第2周：建立巡查制度（每天走一遍全场，拿个本子记录发现的问题）→开始追闭环
- 第3周：品牌内容流程建立（各板块提交→审核→发布）
- 第4周：CRM表格搭建+安全检查制度
- 第2个月：线上商城上架
- **前3个月的目标不是"6大职能全部启动"，是"P0职能跑稳了"**

### 角色B：引擎A主理人（被运营卫星"监督"的板块负责人）

**体验**：运营卫星早上来巡查我负责的区域→发现垃圾桶满了→拍照发到群里→"@我 请处理"——最开始可能会觉得"你凭什么管我"

**关键**：运营卫星的监督不是"挑刺"，是**帮各板块发现盲区**。引擎A主理人每天忙着备菜出餐，不一定有时间注意到自己区域外的垃圾桶。运营卫星的角色是"多了一双眼睛"——不是增加负担，是帮各板块兜底。
