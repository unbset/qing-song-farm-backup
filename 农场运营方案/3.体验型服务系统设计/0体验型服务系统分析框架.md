# 青松农场体验型服务系统 · 分析框架

> **版本**：V2.0
> **修正记录**：V1.0以"一个画像"为分析单位；V2.0改为以"家庭/群体"为分析单位，每个场景下识别所有角色并分别分析
> **修正原因**：农场来的客人不是"一个人"，是一个群体（家庭/情侣/朋友团/团队）。每个角色都有独立的需求和服务触点，不能合并处理。

---

## 框架结构（六层）

```
第①层 · 人与关系（Roles & Relationships）
第②层 · 场景（Context）
第③层 · 体验任务（JTBD深化）
第④层 · 触点服务需求（Touchpoint Needs）
第⑤层 · 农场服务方案（Service Response）
第⑥层 · 能力边界（Capability Boundary）
```

---

## 第①层 · 人与关系（Roles & Relationships）

**核心问题**：这次来的有哪些人？他们是什么关系？

### 第一步：识别角色

对一个到访群体，所有在场的人都是客人，需要分别分析。

| 角色    | 定义            | 常见身份         |
| :---- | :------------ | :----------- |
| 核心体验者 | 这次来的主要目的对象    | 上课的孩子、过生日的孩子 |
| 决策者   | 决定来不来、付钱的人    | 妈妈、组织者       |
| 陪同者   | 跟着来但不直接参与核心体验 | 爸爸、爷爷奶奶、朋友   |
| 附加角色  | 临时出现或不可预期     | 婴儿、宠物        |

### 第二步：每个角色的独立分析

对每个角色，输出：

```
角色名称：[身份]

存在意义：（"为什么这个角色会出现在这个场景中"——不是分析他想什么，是先确认他为什么在场）
  └── 例：爸爸是陪同者，但他来了就是客人

基本画像：（年龄/身份/可能的兴趣）
  └── 从8类画像中选择匹配，或新建

核心动机：（他来这一趟要什么？）
  └── 可能和核心体验者完全不同

情绪状态：（来之前的状态/在场时的情绪变化基线）

最怕什么：（什么情况会让他觉得这趟白来了、或不想再来）
```

### 角色关系分析

| 维度 | 分析 |
|:---|:---|
| 角色间的关系 | 夫妻/亲子/祖孙/朋友/同事 |
| 决策权分布 | 谁决策/谁影响决策/谁不参与决策 |
| 角色间的情绪影响 | A的情绪波动会影响B吗？ |
| 服务优先级 | 谁的体验优先保障？谁的体验是增值方向？ |

## 第②层 · 场景（Context）

**核心问题**：这群人在什么状态下需要你？

和V1.0一致，但分析时以"群体决策"为视角：

```
触发场景：这个家庭/群体为什么决定现在来？
决策方式：谁起意、谁拍板、谁影响决策？
决策周期：从有念头到出发，多久？
到店时间：周中/周末？上午/下午？
停留时长：计划待多久？实际可能待多久？
季节/天气敏感度：受不受天气影响？
```

## 第③层 · 体验任务（JTBD深化）

**核心问题**：这次来的每个人，分别要完成什么任务？

核心体验者、决策者、陪同者——三类角色的任务通常完全不同。逐层拆开。

### 功能任务（要做的事）

```
核心体验者：____
决策者：____
陪同者：____
附加角色：____
```

### 情绪任务（要感受的状态）

```
核心体验者：从__到__
决策者：从__到__
陪同者：从__到__
```

### 社交任务（要展示什么）

```
核心体验者：____
决策者：____
陪同者：____
```

### 认同任务（要确认什么身份）

```
核心体验者：____
决策者：____
陪同者：____
```

**判断标准**：如果某个角色的四层任务全部填不出来——要么是这个角色不该出现在这个场景中，要么是对他的理解还不够。

## 第④层 · 触点服务需求（Touchpoint Needs）

**核心问题**：全过程中，每个角色在每个触点需要什么？

### 七个触点 × 所有角色

| 触点 | 核心问题 | 核心体验者 | 决策者 | 陪同者1 | 陪同者2 |
|:---:|:---|:---|:---|:---|:---|
| 1.触发 | 为什么现在来？ | — | 刷到什么/听谁说 | — | — |
| 2.决策 | 敢不敢付钱？ | — | 看什么信息决定 | — | — |
| 3.到达 | 第一印象？ | 看到什么 | 环境值不值 | 有没有事做 | 有没有事做 |
| 4.核心体验 | 时间花得值不值？ | 课程好不好玩 | 孩子开不开心 | 我有没有事做 | 我有没有事做 |
| 5.服务接触 | 该出现的人出现没？ | 老师好不好 | 有没有人理我 | 有没有人理我 | 有没有人理我 |
| 6.离开 | 带走什么？ | 成品/记忆 | 孩子开不开心 | 我今天过得怎么样 | 我今天过得怎么样 |
| 7.后续 | 还会再来吗？ | — | 下次报不报 | — | — |

**重点是陪同者的触点**——这是最容易出增值消费的地方。

## 第⑤层 · 农场服务方案（Service Response）

**核心问题**：对每个角色，农场应该怎么做？

### 每个触点的服务方案

```
触点X：[名称]
  服务目标：
  执行标准：
    1. ____
    2. ____
    3. ____
  负责人：
  物资准备：
  异常预案：
```

### 陪同者增值方案

这是V2.0新增的专项设计板块。对每个陪同者角色，单独设计"他在等候期间可以做什么"。

```
陪同角色：[爸爸/爷爷/奶奶/朋友]

等候时长预估：(如：妈妈+孩子上课1.5小时)

增值服务选项：
  选项A：____（成本：__ 收费：__ 需准备：__）
  选项B：____（成本：__ 收费：__ 需准备：__）
  选项C：____（成本：__ 收费：__ 需准备：__）

自然引导方式：（不是推销，是在他无事可做时顺手指给他）
  └── "那边可以坐着喝杯茶看看松林"
  └── "面包窑今天在做面包，可以去看看"
  └── "后院有鸡，小朋友喂过了你也可以去转转"

转化可能：从陪同者→下次成为决策者或体验者
```

### 关系型客户服务方案

适用于有长期关系的客户（长搭/认领/劳动换薪常客），采用"关系型服务链"：

```
关系维护节点：
  签约日：____（仪式感设计）
  第1个月：____
  第2个月：____
  每季：____
  半年：____
  年度：____
  续约：____
```

## 第⑥层 · 能力边界（Capability Boundary）

**核心问题**：每个角色的需求，我们能满足多少？

```
核心体验者需求 → 能/不能/部分能
决策者需求 → 能/不能/部分能
陪同者需求 → 能/不能/部分能

能做：
  ① ____
  ② ____
  ③ ____

不能做（明确放弃）：
  ① ____（原因：____）
  ② ____（原因：____）

差异化（同行做不了而我们能做的）：
  ① ____
  ② ____
```

## 使用逻辑

### 什么时候用

1. **设计新体验**——农场要推一个新活动时
2. **诊断现有体验**——满意度下降/复购下滑时
3. **季度/半年校准**——检查角色判断和服务方案是否合理时

### 分析结果产出

每次跑完六层，产出：

| 产出 | 给谁用 | 怎么用 |
|:---|:---|:---|
| ①-③的角色+场景+任务分析 | 言渊+运营卫星 | 理解"来的是一群什么人，各要什么" |
| ⑤的服务方案 | 各板块主理人 | 每场活动前按标准执行 |
| 陪同者增值方案 | 运营卫星+各板块 | 让陪同者也有事做、有消费 |
| ⑥的能力边界 | 言渊 | 决定做什么、放弃什么 |

## 风险提示

| 风险 | 表现 | 防范 |
|:---|:---|:---|
| 角色越拆越多，服务方案设计不完 | 每个场景5-6个角色，分析量过大 | 每场景最多分析3个角色（核心体验者+决策者+1个主要陪同者），其余统一归入"其他陪同者"处理 |
| 陪同者方案做成了"找活干" | 陪同者本来想休息，被安排了太多事 | 增值方案设"最低介入原则"——先提供"什么都不做也可以"的选择，再提供增值选项 |
| 角色需求冲突时无法决策 | 妈妈想上课，孩子想玩，爸爸想走 | 第⑤层明确"服务优先级"：核心体验者 > 决策者 > 陪同者 |
