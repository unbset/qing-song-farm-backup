# 青松农场服务设计分析框架（V2.0）

> **版本**：V2.0
> **创建日期**：2026-06-01
> **修正记录**：V1.0发布于2026-06-01；V2.0基于压力测试结论修正——移除"3人团队能力上限"的设计约束，改为"框架随团队成长放大价值"
> **框架性质**：认知脚手架（cognitive scaffold），非操作清单
> **核心功能**：系统性地暴露客户体验链条上"我们不知道什么、我们假设了什么、我们什么时候能确认"

---

## 框架全景图

```
                        ┌──── 选择器 ────┐
                        │ 设计活动→用④⑤⑥   │
                        │ 日常运营→用⑥     │
                        │ 战略校准→用①②③⑨  │
                        └────────────────┘
                              │
                              ▼
① 人（Customer / JTBD）
② 场景（Context）
③ 生产约束（Production Constraint — 仅核心层）
                              │
                              ▼
④ 体验任务（JTBD深化）
    ↓ (情绪曲线与触点设计交替迭代至少2轮)
⑤ 情绪曲线 ⇄ ⑥ 触点系统（P0/P1/P2分级）
                              │
                              ▼
⑦ 服务能力匹配分析
                              │
                              ▼
⑧ 输出：体验旅程 + 触点地图 + 情绪曲线 + 服务设计
                              │
                              ▼
⑨ 数据反馈 → 回到①（画像置信度校准）
```

**8层 + 1选择器 + 1反馈循环**。选择器决定"这次跑哪几层"，反馈循环使框架从静态工具变为动态学习系统。

## 框架的两个底层约束（不可绕过）

这两个约束是框架的"结构钢筋"——不管团队规模多大、使用框架的哪几层，都必须遵守。它们不随团队成长而削弱，反而因团队扩大而更需要被严格执行。

### 约束一：生产刚性

**表述**：核心层（生态种养）的农事节律是体验设计的刚性起点。不由客户需求决定，不由团队规模决定，不由市场趋势决定。

**影响范围**：仅核心层（生态种养）相关的体验设计。引擎A（餐饮）、引擎B（露营住宿）、自然手作卫星、运营卫星不适用此约束。

**执行方式**：在设计核心层体验之前，必须查询生产日历确认窗口期。

| 月份 | 农事阶段 | 可开放的体验 | 禁止开放的阶段 |
|:---|:---|:---|:---|
| 2-3月 | 春播 | 育苗+播种课程 | — |
| 4-5月 | 生长期 | 除草/搭架/施肥课程 | — |
| 5-6月 | 小麦/叶菜采收 | 割麦/收菜体验 | — |
| 7-8月 | 玉米/花生/瓜果采收 | 掰玉米/挖花生/摘瓜果 | 病虫害防治期不开放 |
| 9-10月 | 秋收 | 苹果采收/秋收集市 | — |
| 11-12月 | 休耕/堆肥 | 堆肥制作/土壤检测 | 低温期部分蔬菜不生长 |
| 1月 | 冬修 | 鸡舍修缮共建 | — |

**为什么不可绕过**：违反生产刚性意味着客户体验的场景不存在——12月不可能有掰玉米、3月不可能有割麦。这不是服务设计问题，是物理现实问题。

### 约束二：情绪曲线先于活动设计

**表述**：设计任何新体验前，必须先画出客户的情结曲线（节奏设计），再用曲线指导活动设计。顺序不能颠倒。

**执行方式**（交替迭代流程）：

```
Step 1：基于①人+②场景+④体验任务，画出初版情绪曲线（粗略判断节奏走向）
Step 2：基于初版曲线设计触点草案（每个触点对应曲线的哪一段）
Step 3：对照触点草案修正曲线——每个触点产生的情绪是否匹配曲线预期？
Step 4：调整触点设计使情结匹配曲线
Step 5：稳定后的情绪曲线 + 触点设计 = 终版
```

**至少迭代2轮**。单次画线不做触点设计（曲线没有落地验证），单次触点设计不做曲线对照（活动没有节奏约束）。

**为什么不可绕过**：活动导向的体验设计会自然走向"把活动排满"——因为每个活动都是团队花了成本的，没人愿意砍掉。情绪曲线前置强行建立了一个约束：如果这个活动让情绪曲线走平或走低，就砍掉或调整它，不管花了多少成本设计它。

## 八层详解

### 第①层：人（Customer / JTBD）

**输入**：8类画像（详见《客户画像与体验任务分析.md》）
**画像分类主轴**：客户与真实生产的关系深度（由浅到深）

| 层级 | 画像 | 关系深度 | 置信度 | 数据来源 |
|:---:|:---|:---:|:---:|:---|
| L0 | 内容创作者型博主/KOC | 来取材 | ★☆☆☆☆ | 零数据，纯假设 |
| L1 | 城市逃离型情侣/年轻夫妇 | 看到了 | ★★★★☆ | 现有散客记录 |
| L1 | 银发活力型退休人群 | 看到了 | ★☆☆☆☆ | 零数据，纯假设 |
| L1 | 疗愈型独行客 | 看到了 | ★☆☆☆☆ | 零数据，纯假设 |
| L2 | 亲子教育型妈妈 | 学到了 | ★★★☆☆ | 引流课记录<20条 |
| L2 | 自然探索型儿童/青少年 | 上手了 | ★☆☆☆☆ | 零数据，纯假设 |
| L3 | 团建/聚会型B端 | 参与了 | ★★☆☆☆ | 团建记录<5条 |
| L4 | 深度归属型：长搭·认领·劳动换薪常客 | 有我的印记 | ★★★★☆ | 现有长搭客户 |

**置信度使用规则**：
- ★★★★☆：可作为资源配置的核心依据
- ★★★☆☆：可作为参考，但需设置验证节点
- ★★☆☆☆：不作为独立资源配置依据，需与其他画像合并判断
- ★☆☆☆☆：仅作为"值得关注的方向"，不分配实质性资源

**使用频率**：新场景设计时使用。画像整体校准每季度一次。

---

### 第②层：场景（Context）

**输入**：触发场景/决策方式/决策周期/计划vs冲动/结伴方式/停留时长

**核心分析维度**：

| 维度 | 分析问题 | 对设计的影响 |
|:---|:---|:---|
| 触发场景 | 客户在什么状态下想起你？ | 决定内容策略和触达时机 |
| 决策方式 | 理性决策还是冲动决策？ | 决定页面信息密度和决策辅助 |
| 决策周期 | 从看到到决定多久？ | 决定预热窗口和信息触达节奏 |
| 计划vs冲动 | 来之前有没有详细计划？ | 决定体验的开放度（结构化vs自由） |
| 结伴方式 | 一个人、情侣、家庭还是团体？ | 决定空间布局和服务密度 |
| 停留时长 | 能待多久？ | 决定体验深度和触点数量 |

**使用频率**：每次设计新体验时必须分析。

---

### 第③层：生产约束（Production Constraint）

**适用范围**：仅核心层（生态种养）相关体验。引擎A/B、卫星板块不适用。

**执行动作**：

```
当前场景想做什么体验？
  → 查询生产日历（见约束一）
    → 窗口期内 → 继续
    → 窗口期外 → 调整体验方向或等待下一季
```

**使用频率**：每次设计核心层体验时必须查询。

---

### 第④层：体验任务（JTBD深化）

**将客户需求拆解为四层任务**：

| 任务类型 | 定义 | 设计导向 | 示例（亲子教育型） |
|:---|:---|:---|:---|
| 功能任务 | 客户要完成的具体事务 | 效率+完成度 | 孩子能在安全环境下动手 |
| 情绪任务 | 客户要感受到的状态 | 体验节奏 | 妈妈能放松半天 |
| 社交任务 | 客户要在社交中展示什么 | 内容设计 | 拍出"孩子在自然中成长"的照片 |
| 认同任务 | 客户要确认什么身份 | 调性传达 | "我是重视自然教育的妈妈" |

**一个体验必须同时满足四层。** 缺少任何一层，客户的需求就没有被完整回应。常见错误是只做了功能任务（设计了活动内容），忽略了情绪任务（节奏太平）和社交任务（没有出片点）。

**使用频率**：每次设计新体验时必须分析。

---

### 第⑤层：情绪曲线

**位置**：第④层之后，与第⑥层交替迭代。

**核心逻辑**：农场体验的本质是节奏设计——不是全程高能刺激，而是**慢→快→慢**。

**标准曲线参考**：

```
情绪
  ↑
  │                      体验高潮（面包出炉/
  │    期待感         自己摘的菜上桌/篝火点燃）
  │      ↙                   ↗
  │    /                   /           平静满足
  │   /   松弛感           /            ↙
  │  /    ↙              /           /
  │ / 放松             /   过渡     /
  │/                 /           /
  └────────────────────────────────────────────► 时间
  到达  →  漫步/咖啡  →  核心体验  →  收尾  →  离开
  慢         慢            快          慢
```

**各画像曲线差异**：

| 画像 | 曲线特征 | 设计要点 |
|:---|:---|:---|
| 城市逃离型 | 平缓上升，不需要高潮 | 舒服最重要 |
| 亲子教育型 | 孩子高亢↗，妈妈平和→ | 孩子的兴奋点+妈妈的休息区 |
| 银发活力型 | 温和上升→平稳 | 节奏不能太快，留聊天间隙 |
| 内容创作者型 | 快速找到拍摄点↗→持续→走 | 不需要节奏设计，提供取景点 |
| 深度归属型 | 平稳满足（像回家） | 稳定感优于惊喜 |
| 疗愈独行型 | 从低慢慢回升→平缓 | 不打扰比什么都重要 |

**使用频率**：每次设计新体验时使用。与第⑥层交替迭代至少2轮。

---

### 第⑥层：触点系统

**7个触点、3个等级**。分级标准基于"客户不满意的后果严重程度"，不是基于团队当前能力。

| 触点 | 优先级 | 分级依据 | 设计标准 |
|:---|:---:|:---|:---|
| ① 触发 | P2 | 内容不好不会导致体验失败，但会影响到店率 | 持续产出即可，不追爆款 |
| ② 决策 | P1 | 信息不清晰会流失客户，但流失可以忍受 | 价格+内容+真实照片透明 |
| ③ 到达 | **P0** | **第一印象决定70%以上体验评价** | 导航顺+洗手间干净+有人迎接 |
| ④ 体验 | **P0** | **这是客户来的唯一理由** | 核心内容质量达标 |
| ⑤ 服务 | **P0** | **人的温度不可替代——也是最容易被压缩的** | 热情+有回应+不打扰 |
| ⑥ 离开 | **P0** | **带走什么决定复购和传播** | 至少有1件可带走的东西 |
| ⑦ 后续 | P1 | 不做不会导致单次体验失败，但复购率下降 | 记录信息+社群入群 |

**P0/P1/P2的团队分工建议**（随团队规模变化）：

| 团队规模 | P0触点分工 | P1触点分工 | P2触点分工 |
|:---:|:---|:---|:---|
| 3人 | 全员保P0 | 有空再做P1 | 不做P2 |
| 5人 | 专人负责④体验+⑤服务 | 专人负责②决策+⑥离开 | 运营负责①触发+⑦后续 |
| 8人+ | 每个P0触点有独立负责人 | ②⑦常态化 | ①开始系统化 |

**使用频率**：日常运营每天使用——检查当天P0触点是否达标。

---

### 第⑦层：服务能力匹配分析

**每个触点做三层匹配**：

```
用户期待是什么？（从①④层得出）
  → 农场现有能力能不能满足？（场地/人员/运营复杂度）
    → 差距在哪里？
      ├── 需补充服务设计（流程缺失）
      ├── 需补充流程（分工不清晰）
      ├── 需补充人（人手不够）
      └── 需砍掉需求（农场本来就不适合做）
```

**砍需求的标准**：如果用户期待与农场能力之间的差距需要"增加超出经营范围的设施/人员/资质"才能填补，则应该砍掉这个需求，而不是硬做。

**使用频率**：每次设计新触点时使用。

---

### 第⑧层：输出

**标准的输出格式**：

```
1. 画像：______（从8类中选择）
2. 场景：______（触发场景+结伴方式+停留时长）
3. 生产约束：______（已确认/不适用）
4. 体验旅程（文字描述）：
   到达前 → 到达 → 核心体验 → 收尾 → 离开 → 后续
5. 触点地图（7个触点的设计要点）：
   触发：______
   决策：______
   到达：______（P0）
   体验：______（P0）
   服务：______（P0）
   离开：______（P0）
   后续：______
6. 情绪曲线附件：（附曲线图）
7. 能力匹配结论：______（能做/不能做/需调整）
8. 通过/不通过/有条件通过：______
```

**使用频率**：每次新体验设计完成时输出。

### 第⑨层：数据反馈

**为什么需要这一层**：框架的全部输入（画像假设、场景判断、情绪曲线）都是基于当前时点的有限认知。没有反馈循环，框架从第1个月到第12个月使用的都是同一组假设，而运营实际已经变了。

**反馈内容**（每季度执行）：

| 反馈项 | 数据来源 | 校准对象 |
|:---|:---|:---|
| 各画像客户的实际到店比例 | 运营记录 | 画像权重+优先级 |
| 各画像客户的客单价和复购率 | 财务记录+CRM | 画像分类（是否需要合并/拆分） |
| P0触点客户满意度评分 | 评价收集 | P0触点设计标准 |
| 表现与框架预期不符的场景 | 运营团队反馈 | 场景判断修正 |
| 新增的客户行为模式 | 运营卫星观察 | 新画像假设或现有画像修正 |

**归零复盘**（每6个月一次）：

```
1. 各画像的实际客户数据与框架输入对比——验证了多少？证伪了多少？
2. 生产约束层的判断是否准确——有没有错过窗口期或误判禁止期？
3. 情绪曲线假设是否匹配实际客户反馈——客户体验后的真实情绪是什么？
4. 触点P0/P1/P2分级是否需要调整——客户投诉集中在哪些触点？
5. 框架的底层约束是否被遵守——有没有绕过生产刚性或情绪曲线前置？
```

**使用频率**：季度校准，半年归零复盘。

## 使用选择器

不是每次使用都需要跑通全9层。根据使用场景选择需要的层：

| 使用场景 | 必须跑的层 | 可选层 | 不需要的层 |
|:---|:---|:---|:---|
| 优化现有体验（如调整课程流程） | ⑤⑥ | ④⑦ | ①②③⑧⑨ |
| 设计全新体验（如首次推探索营） | ①②④⑤⑥⑦⑧ | ③（核心层相关时必须） | ⑨（尚无数据） |
| 日常运营巡检 | ⑥（仅P0触点） | — | ①②③④⑤⑦⑧⑨ |
| 季度战略校准 | ①②⑨ | ③④⑤⑥⑦⑧ | — |
| 半年归零复盘 | ①-⑨全层 | — | — |

**指导原则**：框架的价值在于约束力（两个底层规则）和反馈循环（第⑨层），不在于"跑完8层"。只跑第⑥层触点系统也能提升日常运营质量——从第⑥层开始，需要深挖时再向前回溯。

## 框架使用风险提示

### 风险一：框架与业务增长脱节

**表现**：团队从3人扩展到6人时，各岗位开始各自使用框架的不同层，但没有统一的数据反馈层对齐各岗位对画像、场景、情绪曲线的判断。运营主管的触点设计与种植养殖主管的生产约束判断形成矛盾，言渊的战略判断与运营主管的日常执行出现偏差。

**严重程度**：高。会导致框架内部逻辑不自洽——不同岗位基于框架做出的决策相互冲突。

**防范手段**：每周15分钟全员对齐机制（不是复盘"今天发生了什么事"，是对齐"我们现在用的是框架的哪几层、每层的核心假设是什么"）。框架结构本身不需要调整，分工深度需要调整。

### 风险二：框架被当作真理而非假设

**表现**：团队开始说"框架上说这个画像的优先级是最高"而不是"框架假设这个画像优先级最高，我们正在验证"。

**严重程度**：致命。框架的所有输入都是基于当前时点有限认知的假设，被当作真理使用时，会阻止团队发现框架错误。

**防范手段**：在第⑨层数据反馈中设置"画像置信度"标记（见第①层置信度等级），并在每月运营报告中追踪——"本月框架的预测与实际情况的匹配率是多少"。

### 风险三：情绪曲线前置被形式化

**表现**：团队为满足流程要求画了一条曲线，但在触点设计中完全不参照它。曲线变成文件里的装饰品。

**严重程度**：中。会导致框架的"设计哲学底线"被架空。

**防范手段**：在输出模板（第⑧层）中将"情绪曲线"列为附件，并标注"每个触点对应的曲线位置"。缺少这个标注的输出不被认为是通过。

### 风险四：生产约束被"灵活处理"

**表现**：客户要求12月体验掰玉米，团队认为"客户是上帝"于是用冷冻玉米替代新鲜采摘，名为"掰玉米体验"。

**严重程度**：高。违反生产刚性意味着客户体验的场景不存在——用冷冻玉米替代新鲜采摘不是"灵活"，是欺诈。这比不做更糟糕，因为一旦客户发现（玉米不是从地里掰的），信任崩塌不可逆。

**防范手段**：生产约束的判断权归种植养殖主管，运营卫星和言渊均不得覆盖。如果客户有不符合生产日历的需求，由种植养殖主管直接回答"这个时间做不了，但可以做XXX"。
