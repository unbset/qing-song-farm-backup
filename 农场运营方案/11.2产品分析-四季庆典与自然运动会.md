## 前置说明：为什么归引擎B

四季庆典和自然运动会的本质是**大型活动策划与执行**，不是课程或体验内容。对比：

| 维度 | 课程/体验（自然手作卫星） | 活动/庆典（引擎B） |
|:---|:---|:---|
| 交付核心 | 老师+教案 | 场地+接待+协调 |
| 频次 | 每周/每两周 | 每季度/每半年 |
| 涉及板块 | 卫星内部 + 配合协作 | **全农场所有板块协同** |
| 客户容量 | 10-30人/场 | 100-500人/场 |
| 收入模式 | 课程费 | 入场+餐饮+零售+露营综合消费 |
| 人流动线 | 老师带队 | 需要引导+分流入场 |

引擎B已经具备团建/宴会的接待能力，增加大型活动策划是同一套能力的横向扩展。

## 1. 飞轮定位

**主定位**：引流入口（一次性最大规模的获客事件）

四季庆典和自然运动会是农场**单次触达客户量最大的产品**。一场活动可以带来100-500人到店，其中大量是首次到店的新客户。它们是农场的"年度获客大事件"。

**辅助作用**：
- 传播杠杆（活动期间的画面——满松林的人在跑/篝火晚会/长桌宴——天然出片，一场活动的内容够发一个月小红书）
- 利润中心（入场费+餐饮+零售+露营的综合消费，单日营收可能超过平时一周）

## 2. 目标客群

### 四季庆典

每个季节的庆典面向的客群略有不同：

| 庆典 | 预计时间 | 主力客群 | 附加客群 |
|:---|:---|:---|:---|
| **开耕节（春）** | 3月下旬/4月上旬 | 带孩子家庭（自然教育老客户） | 想参加"春天第一场户外活动"的年轻人 |
| **夏夜星空节（夏）** | 7月下旬（暑假） | 露营客户、年轻情侣、亲子家庭 | 想带孩子露营过夜的家庭 |
| **丰收节（秋）** | 10月上旬（国庆前后） | 所有家庭客户 | 想体验丰收氛围的城市成年人 |
| **冬至围炉节（冬）** | 12月下旬 | 农场老客户、朋友聚会 | 想体验冬日篝火+围炉氛围的人 |

### 自然运动会

| 项目 | 内容 |
|:---|:---|:---|
| 定位 | 家庭运动日——"周末带孩子在松林里跑一跑" |
| 预计时间 | 春季运动会（5月上旬，不冷不热）/ 秋季运动会（9月下旬） |
| 主力客群 | 带孩子家庭（4-10岁孩子的家庭为主） |
| 定价方式 | 家庭套票：68-98元/组（含2大1小或1大1小，含3-5个项目参与资格） |

### 决策逻辑（以首次到店的客户为例）

```
在小红书刷到"农场丰收节" → 看到图片（松林+长桌+南瓜/玉米+很多人在玩）→ 
"好像很好玩" → 看到有入场券（19.9元早鸟券/现场票29.9元）→ 买了 → 
周末带家人来 → 在现场玩了半天 + 吃饭 + 可能还买了点东西回去 → 
满意 → 关注农场后续活动 → 成为老客户
```

## 3. 核心体验

### 四季庆典

**开耕节**：
"松林边上的第一块地被翻开了，孩子们排队领了种子，蹲在地边种下去。旁边有长桌上摆着刚蒸好的青团。风吹过来的时候，好像整个农场都在醒。"

**夏夜星空节**：
"太阳落山后，松林里的灯串亮了。有人在唱歌、有人在烤串、有人铺了垫子在草地上看星星。孩子手里拿着萤火虫灯在跑——其实只是一个手电筒上贴了黄色玻璃纸，但他觉得那就是萤火虫。"

**丰收节**：
"有南瓜堆成的塔、有玉米围成的迷宫、有掰玉米比赛——大人比孩子更投入。结束时每人带走自己掰的玉米。停车场有一半的车后备箱里装着一个南瓜。"

**冬至围炉节**：
"天黑得很早，但松林中心烧着一大堆篝火。人们围着火坐着，有人在烤棉花糖、有人在喝热红酒、有孩子在旁边堆松枝。没人看手机。"

### 自然运动会

"草坪上一共设了5个游戏点。孩子拉着家长挨个去打卡——飞盘投准、两人三足、松果掷远、障碍跑、亲子跳绳。每个点打卡后盖一个章，集齐5个章去换一个小奖品。孩子们跑来跑去，家长跟在后面跑。没有一个孩子在玩手机。"

## 4. 交付标准（+扩展：活动策划全流程）

### 4.1 四季庆典策划框架（以丰收节为例，其他可参照此结构调整）

#### 筹备期（活动前1-2个月）

| 时间节点 | 动作 | 负责人 |
|:---|:---|:---|
| 活动前8周 | 确定活动日期（避开法定假日调休日） | 引擎B主理人 |
| 活动前6周 | 确定活动方案（内容/预算/各板块分工） | 引擎B主理人 + 各板块主理人会 |
| 活动前4周 | 上线宣传（小红书/朋友圈/客户群/大众点评） | 运营卫星 |
| 活动前3周 | 各板块确认物料准备进度 | 各板块主理人 |
| 活动前2周 | 早鸟票开售（价格低于现场票30-50%，催化决策） | 运营卫星 |
| 活动前1周 | 确认天气预报 + 备选方案 | 引擎B主理人 |
| 活动前1天 | 场地搭建 + 物料到位 + 各环节走一遍 | 引擎B主理人 + 全体员工 |

#### 活动当日分工

| 区域/环节 | 谁负责 | 需要什么 |
|:---|:---|:---|
| 入场签到 + 指引 | 引擎B（1-2人） | 签到桌+到店礼（如有）+活动地图 |
| 餐饮区（中心厨房） | 引擎A（正常运营） | 增加备货量，预估为平时的3-5倍 |
| 丰收体验区（掰玉米/挖红薯等） | 核心层 + 自然手作卫星 | 划定区域+工具+标识 |
| 手作体验区 | 自然手作卫星（1人） | 材料包+成品展示 |
| 游戏区（拔河/投掷赛等） | 引擎B（1人） | 道具+奖品 |
| 音乐/氛围区 | 引擎B（音响设备） | 蓝牙音箱+歌单+篝火盆（如是夜场） |
| 摄影记录 | 运营卫星（1人） | 相机/手机 |
| 机动/紧急处理 | 引擎B主理人 | 急救包+对讲机 |

#### 活动结束后

| 动作 | 时间 | 负责人 |
|:---|:---|:---|
| 场地恢复（拆搭建物+清理垃圾） | 活动结束后2小时内 | 全体员工 |
| 发活动照片到客户群+朋友圈 | 活动后24小时内 | 运营卫星 |
| 活动复盘会（什么做得好/什么需要改进） | 活动后1周内 | 引擎B主理人 |

### 4.2 自然运动会策划框架

自然运动会比四季庆典更轻量——不需要主题装饰，不需要舞台，核心就是**5个游戏点+打卡集章+奖品兑换**。

| 时间 | 动作 |
|:---|:---|:---|
| 活动前4周 | 确定活动日期（一个周末，选一天或两天都办） |
| 活动前2周 | 发布活动信息+开放报名（家庭套票68-98元） |
| 活动前1天 | 5个游戏点布置到位 + 打卡地图印刷（或电子版） |
| 活动当日 | 签到→领打卡地图→自由参与各游戏点→集章→换奖品 |
| 活动后 | 发活动照片到客户群+朋友圈 |

**自然运动会的5个游戏点建议**（尽量使用低成本/旧物利用的道具）：

| 游戏点 | 所需道具 | 适合人群 | 难度 |
|:---|:---|:---|:---|
| 松果掷远/掷准 | 松果一堆+目标圈 | 亲子、儿童 | 低 |
| 两人三足 | 绑腿带若干 | 亲子 | 低 |
| 草地障碍跑 | 锥桶/绳子/垫子 | 儿童 | 中 |
| 亲子跳绳 | 跳绳若干 | 亲子 | 低 |
| 拔河（已有） | 拔河绳 | 团体 | 低 |

**奖品**：
- 集3个章 → 一张"下次来农场餐饮9折券"
- 集5个章 → 一块手作卫星的小手工皂 + 9折券
- 奖品成本极低，但"集章"这个过程本身让孩子有动力跑完全部点

### 4.3 品质底线

| 项目 | 标准 |
|:---|:---|:---|
| 入场动线 | 签到→领地图→分流到各区域→餐饮区在中心位置（方便随时购买）→出口与入口分离（避免逆流） |
| 备用方案 | 如遇大雨，四季庆典减少户外环节，转入室内空间/大棚；自然运动会直接取消或改期（运动会核心在户外） |
| 垃圾管理 | 增加垃圾桶数量（平时3倍），每半小时巡视清空一次。活动结束后场地恢复原样 |
| 安全 | 活动区域划定边界+警戒线；急救包常备；员工对讲机随时联系 |

## 5. 定价与成本结构

### 四季庆典

| 项目 | 内容 |
|:---|:---|:---|
| 入场券 | 早鸟票19.9元/人 → 现场票29.9元/人。**为什么不收免费？**——免费的客户质量低、到场率低（买了票不来90%，免费的不来70%）。19.9元筛选了"真的想来"的客户，到场率可到80%+ |
| 家庭套票 | 早鸟48元/组（2大1小）→ 现场68元/组 |
| 预期到场人数 | 丰收节150-300人（第一年）/ 夏夜节80-150人（过夜人数少一些） |
| 收入来源 | 入场券收入 + 引擎A餐饮收入（预估人均消费40-60元）+ 零售产品收入 |
| 单场营收预估（丰收节200人到场） | 入场：200×25≈5000元 + 餐饮：150人×50≈7500元 + 零售：50人×40≈2000元 = **单场14500元** |
| 成本 | 活动物料1000-2000元（搭建设施/装饰/道具）+ 员工加班费 + 食材成本 |
| 毛利率预估 | 单场净利润约8000-10000元 |

### 自然运动会

| 项目 | 内容 |
|:---|:---|:---|
| 家庭套票 | 68-98元/组（2大1小或1大1小） |
| 预期到场 | 50-100组家庭（150-300人）/天 |
| 收入 | 套票收入 + 餐饮收入 |
| 成本 | 道具费（一次性投入约500元）+ 奖品成本（约500元）+ 员工加班费 |
| 毛利率预估 | 70-80%（成本主要为人工） |

## 6. 协作关系（全农场协同——这是复杂度最高的产品）

| 协作方 | 配合什么 | 谁主导 |
|:---|:---|:---|:---|
| **引擎B主理人** | 活动统筹（方案→分工→执行→复盘） | ✅ 总负责 |
| **引擎A（餐饮）** | 活动当日餐饮供应（备货量为平时的3-5倍）+ 特色活动餐食（如开耕节的青团、丰收节的蒸南瓜、冬至节的围炉火锅） | 引擎B提前2周告知预估人数，引擎A准备食材 |
| **核心（生态种养）** | 提供活动中的体验内容（丰收节的掰玉米/挖红薯、开耕节的播种体验） | 引擎B提前1个月排入核心层种植计划（丰收节的玉米需要提前种好） |
| **自然手作卫星** | 提供活动中的手作体验环节（丰收节的南瓜手作、冬至节的松枝花环） + 为自然运动会提供小奖品（手工皂） | 引擎B提出需求，自然手作卫星出老师+材料 |
| **运营卫星** | 活动前：线上宣传 + 早鸟票上架 + 客户群推送；活动中：摄影记录；活动后：活动照片发布 | 运营卫星总负责宣传，引擎B提供内容素材 |
| **全体员工** | 活动当日各司其职（提前分配岗位） | 引擎B主理人统一调配 |

## 7. 风险评估

| 风险类别 | 风险描述 | 概率 | 影响 | 应对 | 剩余风险 |
|:---|:---|:---|:---|:---|:---|
| **运营风险** | **天气不好**——活动当天大雨/大风，室外活动无法进行 | 中 | **极高** | 四季庆典：提前1周确认天气预报，备选方案（调整活动内容/缩减环节/转移到室内）至少提前3天告知已购票客户。自然运动会：直接取消或改期（运动会核心在户外，无法室内替代） | 可承受（提前告知+退票机制） |
| **运营风险** | **到场人数低于预期**——宣传了但当天只来了50人，和准备了300人份的物料/食材不匹配 | 中 | 中 | 早鸟票数量可作为到场率的预测指标（卖了50张早鸟票=预估到场100-120人）。根据早鸟票销量在活动前1周调整备货量。食材备货按"早鸟票数×到场率80%+现场票浮动"计算 | 可承受 |
| **安全风险** | 活动人多，发生走失/摔倒/冲突等意外 | 低 | 高 | 活动区域边界清晰+警戒线+签到留手机号+ 现场广播系统 + 员工划分网格责任区 | 可承受 |
| **品牌风险** | **活动质量低于客户预期**——客户花了入场费+路上时间来了，觉得"就这？"→负面传播 | 中 | 高 | **第一次做四季庆典时要保守**——宁可活动内容少一点、每个环节精致一点，也不要安排太多内容但每个都很粗糙。第一次丰收节只做3个体验区（掰玉米+手作+吃），不要贪多。做好了，第二年再加 | 可承受 |
| **运营风险** | 跨板块协作复杂——5个板块同时配合一个活动，信息传递有遗漏 | 中 | 中 | 活动前开一次全员协调会（30分钟），各板块确认自己的分工+物资+时间节点。活动当天用对讲机/群语音联系，引擎B主理人有最终决策权 | 可承受 |

## 8. 增长路径

### 复购

四季庆典和自然运动会的复购逻辑不是"让客户每个周末都来"，而是**让客户记住这个时间、每年都来**。

| 庆典 | 复购锚点 |
|:---|:---|
| 开耕节 | "去年春天在这块地种了番茄，今年来看看长成什么样了" |
| 夏夜星空节 | "去年夏天在这里看星星，今年再来一次" |
| 丰收节 | "去年丰收节掰了玉米，今年还有吗？" |
| 冬至围炉节 | "去年围着篝火烤棉花糖，今年再来一次" |
| 自然运动会 | "上次孩子集齐了5个章，这次说还要来" |

**建议**：每次活动结束后，在客户群发一条"下一季活动预告"——"秋天10月丰收节，到时候见"——让客户有一个"等"的感觉。

### 传播

四季庆典是农场全年**最集中的内容产出窗口**。一场活动产出的图片+视频足够运营卫星发1个月的内容。

| 传播渠道 | 内容 | 时间 |
|:---|:---|:---|
| 参加活动的客户发朋友圈 | 活动现场的照片/视频 | 活动当日-次日内 |
| 运营卫星发小红书 | 活动精华照片+"下一季预告" | 活动后3天内 |
| 客户群 | 活动照片+视频集锦 | 活动后24小时内 |
| 大众点评 | 更新活动现场照片（提升其他产品的转化率） | 活动后1周内 |

## 9. 数据与AI融合（△）

| 数据项 | 怎么采集 | 在哪记录 | 用途 |
|:---|:---|:---|:---|
| 到场人数 | 签到计数 | 经营日志-活动记录 | 估算入场费+餐饮营收 |
| 早鸟票→到场率 | 早鸟票售出数 vs 签到数 | 经营日志-活动记录 | 预测到场率、优化早鸟定价 |
| 各板块收入（入场/餐饮/零售） | 收银系统分类 | 经营日志-收入流水 | 评估活动综合ROI |
| 首次到店客户数 | 签到时间"第一次来？" | 经营日志-客流记录 | 活动的引流效果 |
| 活动中的负面反馈 | 现场收集+活动后问卷 | 经营日志-客户反馈 | 下次活动改进 |

## 10. 决策结论

| 项目 | 内容 |
|:---|:---|:---|
| 总体判断 | **做**（但第一年控制规模和频次） |
| 前提条件 | 1. 第一年只做2场——丰收节（秋季）和自然运动会（春季）——验证活动策划能力和跨板块协作流程。夏夜节和冬至节第一年不做，第二年视情况增加 2. 第一场活动前做一次全员分工协调会 3. 各板块确认自己的分工和物资清单 |

## +1 多角色验证

### 角色A：第一次来参加丰收节的家庭（妈妈+4岁孩子）

**体验路线**：在小红书看到丰收节 → 买了早鸟票（19.9元×2+孩子免费）→ 周末开车来 → 签到领了一张活动地图 → 孩子先去了掰玉米 → 又去做了南瓜手作 → 饿了去中心厨房买了点吃的 → 又玩了拔河和投掷 → 临走买了5个现烤面包带走

**加分点**：活动地图标得很清楚，每个点在哪里、距离多远一目了然；中心厨房备货充足，排队不长；走的时候孩子手里拿着自己做的南瓜手工——"看，我做的！"
**扣分点**：玉米地排队有点久（掰玉米太受欢迎了，第一批玉米很快被掰完，等第二批补货等了20分钟）——下次可以分时段放行
**复购意愿**：强。"下次有什么活动还来。"
**传播意愿**：强。当场发了朋友圈+小红书——"今天带娃来农场丰收节，太好玩了。"
**优化建议**：热门体验项目（掰玉米/手作）分上下午两个时段开放预约，避免扎堆排队

### 角色B：引擎B主理人（活动统筹者）

**四季庆典对引擎B最大的考验不是"组织活动的能力"，是"让其他板块按时交付的能力"**——核心层的玉米到底种没种够？自然手作卫星的老师当天会不会另有安排？引擎A的备货量够不够？引擎B主理人在活动中的角色更像"项目总管"——不直接做任何事，但确保每件事有人在规定时间做完。

**跨板块协作是农场的"压力测试"**——如果一次丰收节能顺利办完，说明农场的运营体系已经成熟了。如果办得磕磕绊绊，暴露的问题就是平时没看到的盲区。

### 角色C：农场主管（战略视角）

四季庆典有一个容易被忽略的价值——它是**农场"整理形象"的节奏器**。每个季度一次大型活动，意味着每3个月农场需要"把自己整理一遍"——菜地要整齐、展示台要更新、松林要清理、设备要检修。没有这个节奏，一些维护工作会被日常运营挤掉。一年4次大型活动 = 4次"大扫除+改进"的硬性节点。

---
**最需要注意的运营判断：**  
四季庆典对农场的最大价值不是单场营收，而是**一年4次全员协作的"压力测试"**——每季度一次需要所有板块配合的大型活动，等于给农场设置了4次"整理自己"的硬性节点。菜地要整理、设备要检修、流程要复盘。没有这个节奏，维护工作容易被日常运营挤掉。

**风险中最重要的一条：**  
第一场丰收节宁可做小做精（只设3个体验区），不要贪多设6个区但每个都粗糙——口碑一旦建立，第二年可以扩。
